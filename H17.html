H17 项目管理（一）· 范围进度成本与挣值分析 1 / 14

第 17 小时 · 项目管理（一）· 范围进度成本与挣值分析

第 8 章真题占比 3.8%（21/557）。题量不大，但挣值分析 EVA 是综合知识的必考计算——
几乎每年都有一道"给 PV/EV/AC 求 CV/SV/CPI/SPI 并判断状态"的题。
本学时覆盖 8.1 概述 + 8.2 范围 + 8.3 进度 + 8.4 成本与挣值，即项目管理的计算主战场。

考情定位

四块必拿：① 挣值三参数（PV 计划 / EV 实际完成按预算 / AC 实际完成按实花）；② 四指标判据（CV=EV−AC、SV=EV−PV、负值就是不好；CPI=EV/AC、SPI=EV/PV、小于 1 就是不好）；③ EAC 三种公式（按 CPI 推 / 按原预算 / 同时考虑 CPI 与 SPI）；④ WBS 最小单元 = 工作包，且 WBS 分解的是"交付物"不是"活动"。

记忆口诀

三参数：PV 计划值 ｜ EV 挣值（实完 × 预算单价）｜ AC 实际成本（实完 × 实际单价）。
四指标：CV = EV − AC（负 = 超支）｜ SV = EV − PV（负 = 落后）｜ CPI = EV/AC（<1 超支）｜ SPI = EV/PV（<1 落后）。
EAC：`BAC/CPI`（按当前绩效）｜ `AC+(BAC−EV)`（按原预算）｜ `AC+(BAC−EV)/(CPI×SPI)`（双约束）。
四依赖：强制性（硬逻辑，不可改）· 选择性（软逻辑，可改）· 外部 · 内部。

易错陷阱

EV 和 AC 都是"实际完成的工作"，区别只在计价标准（EV 按预算、AC 按实花），别把 EV 记成"计划完成"。
"软逻辑可以调整来压缩工期，硬逻辑不行" —— 案例题问"如何赶工"时的第一句话。
沉没成本不参与未来决策（已经花掉、收不回来的钱，再纠结也没用）。

论文可用句

在项目监控上，我建立了挣值分析的月度度量机制：以 PV/EV/AC 三个基本量为基础，按 `CV = EV − AC`、`SV = EV − PV`、`CPI = EV/AC`、`SPI = EV/PV` 计算四指标。项目第 5 个月时 CPI = 0.82、SPI = 0.90，双双小于 1，说明成本超支且进度落后；据此定位到"接口联调反复返工"这一根因，通过引入契约测试将返工率从 23% 降到 6%，第 8 个月 CPI 回到 0.97、SPI 回到 1.02，最终在预算内按期交付。

第 8 章知识骨架

8.1 项目管理概述

🎯项目与项目管理

项目

特定条件下、具有特定目标的一次性任务****——一定时间内满足一系列特定目标的多项相关工作的总称

项目管理

运用专门知识/技能/工具/方法，使项目在有限资源限定条件下实现或超过设定的需求和期望

🧱软件项目管理的 4P

对 人员 People · 产品 Product · 过程 Process · 项目 Project 进行分析和管理的活动——目标是按预定成本、进度、质量顺利完成。

心中有数六件事：工作范围 · 可能风险 · 需要资源 · 要实现的任务 · 经历的里程碑 · 花费工作量（成本）与进度安排

💡 管理在技术工作开始之前开始，软件工程过程最后结束时才终止——贯穿全程（判断题）。

8.2 范围管理 · 五过程 + WBS ⭐

📦范围管理五过程

范围计划编制 → 范围定义 → 创建 WBS → 范围确认 → 范围控制

范围管理要确定项目边界——哪些做、哪些不做；让干系人对产品和过程有共同理解

⚠️ 需求无序扩张（范围蔓延）是项目失败最常见原因之一

💡 范围计划描述项目边界；范围管理计划描述"如何管理范围"——两个文档别混。

🌳WBS 工作分解结构

定位

面向可交付成果的层次分解——组织并定义整个项目范围；建立范围基准

工作包（最底层）

便于完整分派给个人/组织；太大难控制、太小耗精力（经验法则 80 小时 / 2 周）

里程碑 ≠ 可交付成果

里程碑关注是否完成（如客户书面认可）；可交付成果是实物（报告/原型/系统）

⚡ 辨析：WBS 分解的是"做什么"，不是"怎么做"；WBS 不是活动清单（活动是后续"活动定义"的产物）。

范围确认六检查 + 范围控制

✅范围确认 · 干系人检查六项

①可交付成果确定、可核实

②每个成果有明确里程碑（可辨别事件，如客户书面认可）

③有明确质量标准，成果与标准有明确联系

④审核和承诺清晰表达（投资人正式同意边界）

⑤范围覆盖所有活动，无遗漏无错误

⑥范围风险可承受，管理层能降低冲击

🚧范围控制

⭐ 原则："决不让步，除非交换"——所有范围变更必须在工期、费用或质量上得到相应变更。

变更原因：外部环境变化 · 计划不周有错漏 · 新技术出现 · 组织变化 · 客户要求变化

控制依据：WBS · 项目进展报告 · 变更请求 · 范围管理计划（有合同的遵守合同条款）

💡 所有变更必须记载；即使"好"的变化也要控制——先估算对资金/进度/风险的影响。

8.3 进度管理 · 六过程 + 两种网络图 ⭐

📅进度管理六过程

① 活动定义 → ② 活动排序 → ③ 活动资源估算 → ④ 活动历时估算 → ⑤ 进度计划编制 → ⑥ 进度控制

在质量、成本目标协调的基础上实现工期目标；按时交付是项目成功的重要标志

🔗PDM 前导图法（节点=活动）

节点 = 活动（含 ES/LS/EF/LF 四参数）；箭线 = 依赖关系

绘图规则：不能有回路 · 不能双向/无箭头 · 只能一个起点一个终点（多起点终点时加虚活动）

FS 最常用；SF 最少用

➡️ADM 箭线图法（箭线=活动）

结构

节点 = 事件（唯一代号，序号沿箭线增大）；箭线 = 活动；只用 FS 关系

虚活动

用虚箭线表示——不占资源不耗时间，只为正确表达逻辑关系/解决多起点终点

💡 辨析：PDM 四种关系都能用；ADM 只用 FS——考试给图认类型。

⚡ 依赖三分类：强制性（硬逻辑/工艺） · 可自由处理（软逻辑/组织） · 外部依赖（项目与非项目活动）。

四种依赖关系 + 逻辑表达三形式

🧩PDM 四种依赖（必背）

FS 完成-开始

后一活动开始要等前一活动完成
最常用

FF 完成-完成

后一活动完成要等前一活动完成

SS 开始-开始

后一活动开始要等前一活动开始

SF 开始-完成

后一活动完成要等前一活动开始
很少用

平行关系（并行）

两项活动同时开始

顺序关系

紧连顺序（完成后马上开始）/ 间隔顺序（完成后隔一段时间才开始）；紧前活动/紧后活动

搭接关系

只有一段时间平行进行

💡 记忆锚：FS = 干完才能开工（默认）；FF = 一起收工；SS = 一起开工；SF = 反常识、基本不考图只考名字。

工作量估算 · LOC 与德尔菲法

📏LOC 代码行估算（教材例）

规模用 LOC（可执行源代码行数）衡量；按历史项目核算单行代码价值

教材例：1 万行 Java ≈ 250kB；项目源文件 3.75MB → 15 万行；投入 240 人·月，万人·月费 1 万元

→ 1LOC 价值 = 240×10000 ÷ 150000 = 16 元/LOC

→ 人·月平均代码行 = 150000 ÷ 240 = 625 LOC/人·月

💡 估算错误是软件项目失败的主要原因之一——软件复杂、历史经验缺、估算工具缺。

📮德尔菲法（专家评估）

结合专家判断 + 三点估算；无历史数据时用；减少人为偏见、防止权威影响过大

要点：无记名填表（a 最小 / m 最可能 / b 最大）→ 组织者算 E = (a+4m+b)/6 汇总中值 → 反馈只给意见不署名 → 多轮重复至共识；过程中不得小组讨论

缺点：过程复杂、耗时长；宽带德尔菲加了协商讨论环节克服此缺点

⚡ 辨析：德尔菲 vs 专家会议法——背对背无记名 vs 当面讨论；德尔菲避免权威左右、碍于情面、不愿改口三缺点。

类比 / 功能点 / COCOMO 估算

🔍类比估算法

适合与历史项目相似（领域/环境/复杂度）的新项目；精度取决于历史数据的完整与准确

⭐ 等价 LOC =（重新设计% + 重新编码% + 重新测试%）÷ 3 × 已有 LOC

教材例：10000 LOC，30% 重设计 + 50% 重编码 + 70% 重测试 → 5000 LOC 等价工作量

🎛️功能点 FP

需求分析阶段基于系统功能估计：数输入/输出/查询/数据文件/外部接口 → 加权乘 → 复杂度调整因子修正

优点：与程序设计语言无关；缺点：主观因素多（权值取值）

🧮COCOMO 模型（结构型估算）

三类型（按开发环境）

组织型 · 半独立型 · 嵌入型

三级（按详细程度）

基本（静态单变量：M = 2.4×kLOC^1.05）→ 中间（+ EAF 调整因子 0.9~1.4）→ 详细（分层/分阶段：模块层·子系统层·系统层三张分级表）

💡 工作量单位人·月、进度单位月；组织型最省、嵌入型最贵——考试考"三级"名称排序与 EAF 范围。

进度控制 · 偏差分析三看 + 调整四情况

🔎分析进度偏差（三看）

① 是否关键活动

关键活动偏差必影响总工期 → 必须更新计划

② 偏差 vs 总时差

偏差>总时差 → 影响总工期；≤总时差 → 总工期无影响（再看自由时差）

③ 偏差 vs 自由时差

偏差>自由时差 → 影响后续活动；≤自由时差 → 无影响，计划可不调整

🛠️进度计划调整四情况

① 关键活动调整（重点）——提前：降资源强度或重新计划缩短工期；落后：缩短后续关键活动持续时间补回来

② 非关键活动调整——时差范围内延长/缩短/挪时间；超出总时差 → 关键路径转移

③ 增减工作项目——只改局部逻辑，不改总逻辑；重算时间参数

④ 资源调整——供应异常时优化资源，前提是工期不变或更合理

⚡ Brooks 法则：为延期的软件项目增加人员将可能使其进度更慢——赶工不能盲目加人。

8.4 成本管理 · 三过程 + 估算三方法

💰成本管理三过程

① 成本估算

编制费用估算书——计划中关键、敏感的部分；与活动资源估算结合

② 成本预算

总成本分摊到各工作包 → 再分到活动 → 定时间计划与累积成本；建立成本基准衡量绩效

③ 成本控制

保证各项工作在预算范围内进行；主要用挣值分析（又称偏差分析法）

📐估算三方法

自顶向下

从整体出发类推历史总成本 → 按比例分摊到各任务——快但粗，适合早期

自底向上

细分到子任务再汇总——准但慢，需详细 WBS

差别估算

综合两者优点：与历史项目类比，类似部分按实际量、不同部分用德尔菲等；缺点 = "类似"界限不易明确

💡 预算三步：分摊到工作包 → 二次分摊到活动 → 定时间计划；工作包预算之和不能超过总预算。

成本类型 · 沉没成本 / 管理储备 / 零基准预算

🏷️成本类型与影响因素

直接成本 vs 间接成本

直接 = 项目专属人力物力；间接 = 租金/保险/管理分摊

沉没成本（隐没成本）

已付出且不可收回——决策时不应考虑（呼应 CH10）

学习曲线

用未掌握的新技术 → 初期尝试试验增加成本；新领域项目远贵于老项目升级

其他影响因素

项目时限（越短越贵，压缩交付还抬风险）· 质量要求 · 保留（为风险预留的成本）

🧯管理储备 vs 应急储备 · 零基准预算

  • 管理储备：为范围和成本的潜在变化预留；使用前必须得到批准；不是成本基线的一部分（含在总预算中）；不是挣值分析的一部分——三条"不是"全考。
  • 应急储备：针对已识别风险的预留（风险应对的"接受"策略）；项目经理可使用
  • 零基准预算 ZBB：不以历史项目为基准——以零为基准估计所有工作任务的成本

💡 辨析：管理储备管"未知"，应急储备管"已知"；一个在基线外、一个在基线内。

挣值分析 EVA · 三个基本量 ⭐⭐⭐

📊挣值分析 = 进度和成本测量技术（偏差分析法）

PV 计划值（BCWS）

计划工作量 × 预算单价
——"计划到今天该干多少钱的活"

EV 挣值（BCWP）

实际已完成工作量 × 预算单价
——"实际干完的活值多少钱"（按预算价）

AC 实际成本（ACWP）

实际工作量 × 实际单价
——"实际花了多少钱"

⚡ 记忆锚：EV 和 PV 都用预算单价（只比工作量）；EV 和 AC 都是实际工作量（只比单价）——EV 永远在中间当桥梁。

💡 相关量：BAC = 完工预算（总预算）；判断口令——看进度比 EV 与 PV，看花钱比 EV 与 AC。

挣值四指标 + 预测 · 例题精算 ⭐⭐⭐

📉四个派生指标

SV = EV − PV进度偏差；<0 落后，>0 提前

CV = EV − AC成本偏差；<0 超支，>0 节约

SPI = EV / PV进度绩效；<1 落后

CPI = EV / AC成本绩效；<1 超支

🔮三个预测值

EAC = BAC / CPI（按当前绩效外推）
EAC = AC +（BAC − EV）（剩余按原预算）

ETC = EAC − AC（完工尚需）
VAC = BAC − EAC（完工偏差；<0 将超支）

TCPI =（BAC−EV）/（BAC−AC）（剩余工作要达到的成本绩效）

🧾经典例题（背数字）

BAC = 100 万 · PV = 45 万 · EV = 40 万 · AC = 50 万

→ SV = 40−45 = −5（落后）

→ CV = 40−50 = −10（超支）

→ SPI = 40/45 ≈ 0.89 · CPI = 40/50 = 0.80

→ EAC = 100/0.8 = 125 万

→ VAC = 100−125 = −25 万（将超支 25 万）

💡 结论话术：项目进度落后、成本超支；若按当前绩效继续，完工需 125 万、超支 25 万——案例题标准答案模板。

⚡ 与你项目记忆联动：CV−70 / SV−40 / CPI 0.844 / SPI 0.905 / EAC 948 / TCPI 1.20——同一套公式。

C截至某时点，实际完成工作所花费的实际成本
D项目总预算
三个基本参数（必须能分清"计划的钱"与"实际的钱"）：PV（计划值 / BCWS）——截至某时点计划完成工作的预算；EV（挣值 / BCWP）——截至某时点实际完成工作的预算（用预算单价 × 实际完成量）；AC（实际成本 / ACWP）——截至某时点实际完成工作实际花的钱。⚠️ EV 和 AC 都是"实际完成的工作"，区别在计价标准：EV 按预算算，AC 按实际花销算。
第8章 · 8.4 挣值分析 EVA 三个基本量
2某项目 PV=100 万，EV=90 万，AC=110 万，则成本偏差 CV 与进度偏差 SV 分别是：
ACV = −20 万（超支），SV = −10 万（进度落后）
BCV = +20 万，SV = +10 万
CCV = −10 万，SV = −20 万
DCV = 0，SV = 0
CV = EV − AC = 90 − 110 = −20 万（负值 = 成本超支）；SV = EV − PV = 90 − 100 = −10 万（负值 = 进度落后）。记忆：都是"EV 减去对方"，负的就是不好。引申两个指数：CPI = EV/AC = 0.82 < 1 → 成本超支；SPI = EV/PV = 0.90 < 1 → 进度落后（指数小于 1 就是不好）。
第8章 · 8.4 挣值四指标
3成本绩效指数 CPI = 0.8，则完工估算 EAC（按当前绩效推算）为：
AEAC = BAC / CPI（总预算 ÷ 成本绩效指数）
BEAC = BAC × CPI
CEAC = AC + BAC
DEAC = BAC − AC
三种完工估算（看题干给的条件选公式）：① 剩余工作按当前绩效走（最常用）：`EAC = BAC / CPI`；② 剩余工作按原预算走（认为前期偏差是偶然）：`EAC = AC + (BAC − EV)`；③ 同时考虑成本与进度约束：`EAC = AC + (BAC − EV) / (CPI × SPI)`。另有 ETC = EAC − AC（完工尚需估算）、VAC = BAC − EAC（完工偏差，负值=预计超支）。
第8章 · 8.4 挣值预测
4范围管理中，"WBS（工作分解结构）"分解的最小单元是：
A工作包（Work Package）
B活动（Activity）
C任务（Task）
D里程碑（Milestone）
WBS 以"可交付成果"为导向逐层分解，最底层的单元叫工作包（Work Package），它是成本与工期估算的最小单位（通常 80 小时以内）。⚠️ WBS 分解的是"做什么（交付物）"，不是"怎么做（活动/步骤）"——把工作包再展开成具体活动，那是进度管理里的活动定义（定义活动过程），两者分属不同知识领域。
第8章 · 8.2 范围管理 · WBS
5进度管理中，活动之间的四种依赖关系里，"强制性依赖关系"指的是：
A工作性质本身决定的、不可改变的顺序（如先写代码后测试）
B由项目团队根据最佳实践自行选择的顺序
C由外部条件（如客户到货时间）决定的顺序
D可以任意调整的顺序
四种依赖关系：① 强制性依赖（硬逻辑）——工作性质决定的固有顺序，不可更改（必须先设计后编码）；② 选择性依赖（软逻辑 / 首选逻辑）——团队基于最佳实践自行选择的顺序，可调整；③ 外部依赖——依赖项目外部因素（供应商到货、政府审批）；④ 内部依赖——项目内部活动间的依赖。⚠️ 案例题常考"软逻辑可以调整来压缩工期，硬逻辑不行"。
第8章 · 8.3 四种依赖关系
6关于成本类型，"沉没成本"的正确处理方式是：
A已经发生且无法收回的成本，决策时不应再考虑
B应计入后续投资决策
C应从项目预算中扣除
D应分摊到后续各阶段
沉没成本：已经发生、无论后续如何决策都无法收回的成本（如已完成但被废弃的模块开发费用）。决策原则：沉没成本不应影响未来投资决策——只看"继续做下去还要花多少 vs 能带来多少收益"。⚠️ 相关概念：管理储备（应对"未知未知"的应急储备，不在成本基准内，动用需审批）｜应急储备（应对"已知未知"，在成本基准内）｜零基准预算（每个预算周期从零开始论证，不参考历史）。

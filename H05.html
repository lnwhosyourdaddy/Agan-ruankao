H05 计算机系统（二）· 操作系统 1 / 28

第 5 小时 · 计算机系统（二）· 操作系统

本学时覆盖 3.6 操作系统 —— 概述、进程与线程、死锁、存储管理、设备管理、文件管理、国产操作系统（信创）。
操作系统是案例题的绝对富矿：PV 操作、页面置换、磁盘调度、磁盘调度计算题几乎年年出现。

考情定位

五块必拿：① 进程三态/五态转换（阻塞不能直接回运行）；② 信号量 PV 操作（P 申请阻塞、V 释放唤醒）；③ 死锁四条件 + 四种处理策略；④ 页面置换算法 FIFO/LRU/OPT + 抖动；⑤ 磁盘调度算法计算（FCFS/SSTF/SCAN）。

记忆口诀

PV 操作：P 申请（S>0 则 S−1 继续；S=0 阻塞），V 释放（S+1 并唤醒一个）。
死锁四条件：互斥 · 占有并等待 · 不可剥夺 · 循环等待——破坏任一即可预防。
四种处理：预防（破坏必要条件）· 避免（安全序列/银行家）· 检测（资源分配图化简）· 解除（撤销进程/剥夺资源）。
磁盘调度：SSTF 平均寻道最短（饿死在调），SCAN 电梯（继续服务同向请求）。

易错陷阱

「阻塞 → 就绪」只能由外部事件驱动（I/O 完成、锁释放），不是被调度；被调度是「就绪 → 运行」。
页面置换与抖动：缺页率高不一定是算法差，可能是分配块数太少导致抖动。
SPOOLing 的本质是"用磁盘当缓冲区，把独占设备改成共享虚拟设备"，别答成"提高磁盘速度"。

第 3 章下集知识骨架

3.6.1 操作系统的定义与两大作用

🖥️定义

操作系统能有效地组织和管理系统中的各种软/硬件资源，合理地组织计算机系统工作流程，控制程序的执行，并且向用户提供一个良好的工作环境和友好的接口。

一句话：操作系统是计算机系统的资源管理者，它含有对系统软/硬件资源实施管理的一组程序。

🎯两大作用（必背）

① 通过资源管理提高计算机系统的效率

让硬件资源被充分利用

② 改善人机界面，向用户提供友好的工作环境

让用户用得方便

🧬四大特征

并发性

共享性

虚拟性

不确定性

口诀：并发 · 共享 · 虚拟 · 不确定（"并发共享"是核心，"虚拟"是手段，"不确定"是结果）

资源管理范围在扩展：传统计算机系统资源分硬件资源（CPU、存储器、I/O 设备）和软件资源（以文件形式保存的程序和数据）。现代计算机系统已扩展到感知、能源、通信资源和服务资源。

操作系统的五大功能 ⭐

① 处理机管理

对处理机的分配和运行实施有效管理。

多道程序环境下，处理机的分配和运行以进程为基本单位，所以处理机管理也称为进程管理。

② 存储器管理

主要任务是对内存进行

分配 · 保护 · 扩充

③ 设备管理

应具有三个功能：

  • 设备分配：按一定原则分配设备（常需缓冲技术和虚拟技术）
  • 设备传输控制：实现物理 I/O 操作（启动设备、中断处理、结束处理）
  • 设备独立性：用户申请的设备与实际操作的设备无关

④ 文件管理

负责文件存储空间的管理：

  • 存储空间的分配和回收
  • 目录管理
  • 文件操作管理
  • 文件保护

⑤ 用户界面

也称用户接口。包括两类：

程序接口
面向开发人员

操作接口
面向普通用户和管理者

顺序口诀：处理机 → 存储器 → 设备 → 文件 → 用户界面（从里到外，从硬件到人）

3.6.1 操作系统的分类（六类）

⏱️分时操作系统

一个计算机系统与多个终端设备连接，把 CPU 工作时间划分为许多很短的时间片，轮流为各终端用户服务。

例：20 个终端，每用户每次 50ms 时间片 → 每隔 1s 即可为所有用户服务一遍。用户感觉整个系统归他一人占用。

四大特点：多路性 · 独立性 · 交互性 · 及时性

⚡实时操作系统（RTOS）

对随机发生的外部事件及时做出响应并处理。

  • 分两类：实时控制系统（数据采集、武器控制、飞机自动驾驶、导弹制导）｜实时信息处理系统（飞机订票、情报检索）
  • 与分时的三点区别：

① 设计目标：分时＝多用户通用系统；实时＝专用系统

② 交互性：分时强；实时弱（仅允许访问有限专用程序）

③ 响应时间敏感度：分时以"用户能接受的等待时间"为依据；实时以"被控对象能接受的延迟"为依据 → 实时更敏感

🌐网络操作系统（三类模式）

使联网计算机能方便有效地共享网络资源、为网络用户提供各种服务的软件和有关协议的集合。

功能：网络通信 · 共享资源管理 · 邮件/文件传输/共享硬盘打印机等服务 · 网络安全管理 · 互操作能力

① 集中模式 — 由分时系统加网络功能演变而来，信息处理和控制集中。UNIX 是典型

② 客户端/服务器模式 — 流行的网络工作模式

③ 对等（P2P）模式 — 各站点对等，无服务中心也无控制中心，具有分布处理与分布控制特征

🕸️分布式操作系统

分布式系统由多个分散的计算机经连接而成，各计算机无主次之分，任意两台可通过通信交换信息。

能直接对各类资源进行动态分配和调度，进行任务划分与信息传输协调，为用户提供统一界面和标准接口。

⭐ 它是网络操作系统的更高级形式：保持网络 OS 全部功能，同时具有透明性、可靠性和高性能。

嵌入式操作系统 与 互联网环境要求

📟嵌入式操作系统五特点

运行在嵌入式智能芯片环境中，对芯片及其操作控制的各种部件装置等资源进行统一协调、处理、指挥和控制。

① 微型化 — 占用资源少、内存少、字长短、能源少

② 可定制 — 能运行在不同微处理器平台，针对硬件变化做配置

③ 实时性 — 过程控制、数据采集、传输通信等要求迅速响应

④ 可靠性 — 关键要害应用还要提供容错和防故障措施

⑤ 易移植性 — 采用 HAL 硬件抽象层 和 BSP 板级支撑包

常见：VxWorks、μLinux、PalmOS、Windows CE、μC/OS-II、eCos

🌍互联网环境对 OS 的五方面要求

① 自主配置和自适应协调

互联网环境下节点数量在变、节点状态在变、系统需求不断变 → 要求能自主配置、自适应协调

② 支持跨网络的互连、互通和协作

有线与无线结合、固定与移动节点动态结合、数据资源与物理传感资源结合、人机交互界面多元化

③ 管理和协调系统资源的共享

资源管理范围扩大到感知/能源/通信/服务资源；每个节点的能源消耗和储备成为重要内容；Internet 搜索已成为 OS 基本功能之一

④ 支持功能、性能和可信性指标动态演化

对运算结果的控制要综合能源消耗、运算精度、快速处理三方面折中

⑤ 可信赖操作系统

构造可信赖系统包括私密性、防卫性、可靠性、安全性、可用性

💡 教材总结：为屏蔽计算机硬件的异构性 → 发展了操作系统；为屏蔽操作系统和编程语言的异构性 → 发展了支撑软件和中间件；为弥补应用软件与开发平台的距离 → 发展了软件框架、设计模式。

3.6.2 前趋图 与 进程的组成

🔗前趋图与前趋关系

前趋图是一个有向无循环图，结点代表各程序段的操作，有向边表示两个程序段操作之间的前趋关系。

Pi → Pj 表示：Pi 执行结束后 Pj 才能执行。Pi 是直接前趋，Pj 是直接后继。

  • 顺序执行三特征：顺序性 · 封闭性 · 可再现性
  • 并发执行三特征：失去封闭性 · 程序与执行活动不再一一对应 · 并发程序间的相互制约性
  • 教材例题：1 个 CPU＋1 台输入设备＋1 台输出设备，每个作业有输入 Ii、计算 Ci、输出 Pi 三段（i＝1,2,3）。

可并行：I2 与 C1｜I3、C2 与 P1｜C3 与 P2

受间接制约：I2/I3 受 I1、C2/C3 受 C1、P2/P3 受 P1

🧩进程的组成（三部分）

定义：进程是程序的一次执行，该程序可以和其他程序并发执行。

① PCB

进程控制块。进程存在的唯一标志 ⭐

② 程序

描述进程要完成的功能。若可被多进程共享，应以可再入（纯）码形式编制——是不可修改的部分

③ 数据

程序执行所需的数据及工作区。只能为一个进程专用，是可修改的部分

⭐ 高频考点：PCB 是进程存在的唯一标志（同理下集作业部分：JCB 是作业存在的唯一标志）

进程的三态模型 与 五态模型 ⭐

  • 运行：进程在处理机上运行。单处理机系统中，处于运行状态的进程只有一个。
  • 就绪：已获得除处理机外的一切所需资源，一旦得到处理机即可运行。

阻塞（等待/睡眠）：正在等待某一事件发生（如请求 I/O）而暂停，即使分配处理机也无法运行。

五态模型：在三态基础上引入 新建态 和 终止态。

  • 新建态：进程刚被创建但还没被提交，等待系统完成创建进程的所有必要信息（分两阶段：①创建管理信息 ②进入就绪态）。有了新建态，可根据系统性能和主存容量限制推迟提交。
  • 终止态：进程终止也分两阶段——①等待操作系统善后处理 ②释放主存。

信号量与 PV 操作 ⭐⭐

🚦信号量基础

荷兰学者 Dijkstra 于 1965 年提出。主要有整型信号量、记录型信号量和信号量集机制。

公用信号量 — 实现进程间的互斥，初值为 1 或资源的数目

私用信号量 — 实现进程间的同步，初值为 0 或某个正整数

信号量 S 的物理意义：

S ≥ 0 → 表示某资源的可用数

S < 0 → 其绝对值表示阻塞队列中等待该资源的进程数

🔻🔺P 操作 与 V 操作（不可分割的原语）

P 操作（申请一个资源）：S := S − 1

  • 若 S ≥ 0 → 执行 P 操作的进程继续执行
  • 若 S < 0 → 置该进程为阻塞状态（无可用资源），插入阻塞队列

V 操作（释放一个资源）：S := S + 1

  • 若 S > 0 → 执行 V 操作的进程继续执行
  • 若 S ≤ 0 → 从阻塞队列中唤醒一个进程并插入就绪队列，然后 V 操作进程继续

⚠️ 两组判断符号最容易记反：

P 操作判断条件是 S < 0 才阻塞（先减再判）；V 操作判断条件是 S ≤ 0 才唤醒（先加再判）。

记忆法：P 先减，减到负数就阻塞；V 先加，加到非正就唤醒。

PV 操作的两个经典应用

🔒① 实现进程互斥

令信号量 mutex 初值为 1：

P(mutex)

临界区

V(mutex)

进入临界区时执行 P，退出时执行 V —— P 和 V 必须成对出现且夹住临界区。

＋

🔄② 实现进程同步（生产者-消费者）

缓冲区可存放 n 件产品，设 3 个信号量：

S — 互斥信号量，初值 1（缓冲区是互斥资源）

S₁ — 同步信号量，初值 n（缓冲区的空闲单元数）

S₂ — 同步信号量，初值 0（缓冲区是否存有产品）

生产者：P(S₁) → 放入 → V(S₂)；消费者：P(S₂) → 取出 → V(S₁)

辨析口诀：互斥看初值 1，同步看资源语义——S₁ 初始是"有多少空位"（n），S₂ 初始是"已放了几件"（0）。

⚠️ 常见陷阱：把 S₁ 初值写成 0、S₂ 初值写成 n —— 正好搞反。想清楚：一开始缓冲区是空的，所以空位数是 n、已有产品数是 0。

高级通信原语 与 死锁的产生

📨进程通信：低级 vs 高级

PV 操作属于低级通信方式，存在两个问题：

① 编程难度大——通信对用户不透明，使用不当容易引起死锁

② 效率低——每次只能送/取一个产品

🚀三种高级通信方式

① 共享存储模式

相互通信的进程共享某些数据结构（或存储区）实现通信

② 消息传递模式

数据交换以消息为单位，用系统提供的一组通信命令（原语）实现，如 Send(A)、Receive(A)

③ 管道通信

管道＝连接一个读进程和一个写进程的共享文件（pipe 文件）。写进程以字符流形式把大量数据送入管道，读进程从管道接收

💀死锁的四个必要条件 ⭐

死锁：两个以上的进程互相都要求使用对方已经占有的资源而导致无法继续运行下去的现象。

三个原因：系统缺少足够资源供进程使用；对互斥资源的共享与并发执行顺序不当；资源分配不当。

① 互斥条件

任一时刻只允许一个进程使用资源

② 不剥夺条件

进程已占用的资源，不会被强制剥夺

③ 请求与保持条件

进程在请求其余资源时，不主动释放已经占有的资源

④ 环路条件

环路中每一条边是进程在请求另一个进程已经占有的资源

死锁的四种处理策略 ⭐⭐

策略做法要点与代价
① 鸵鸟策略不理睬即"不处理"。适用于死锁发生概率很低、且代价可接受的场景
② 死锁预防用某种策略限制并发进程对资源的请求，破坏 4 个必要条件之一· 预先静态分配法 → 破坏"不可剥夺条件"：预先分配所需资源，保证不等待 问题：降低资源利用率和进程并发程度；有时无法预先知道所需资源 · 资源有序分配法 → 破坏"环路条件"：把资源分类按顺序排列，保证不形成环路 问题：限制进程对资源的请求；资源排序占用系统开销
③ 死锁避免不那么严格地限制必要条件，在分配前动态判断是否安全· 最著名的是 Dijkstra 提出的 银行家算法 · 对每个可满足的资源请求加以检测：分配后若进入不安全状态则不予分配；仍处于安全状态才分配 · 比预防策略提高了资源利用率，但检测增加系统开销，算法开销很大
④ 检测与解除对资源分配不加限制（允许死锁产生），定时运行检测程序· 死锁检测：定时运行检测程序判断系统是否发生死锁 · 解除：资源剥夺法（强行剥夺足够资源给死锁进程）｜撤销进程法（按策略逐个撤销死锁进程直到解除）

⭐ 最高频辨析：资源有序分配法破坏的是"环路条件"（不是互斥、不是不可剥夺）；预先静态分配法破坏的是"不可剥夺条件"。

安全状态的定义：系统能按某种顺序 <P₁,P₂,…,Pₙ> 为每个进程分配其所需资源直到最大需求，使每个进程都可顺序完成 → 该序列称为安全序列；不存在安全序列则系统处于不安全状态。

线程 · 与进程的分工

🧵为什么引入线程

传统的进程有两个基本属性：可拥有资源的独立单位 + 可独立调度和分配的基本单位。

问题：进程在创建、撤销和切换中，系统必须付出较大的时空开销，所以进程数目不宜过多、切换频率不宜太高。

引入线程后把这两个属性分开：

  • 线程 = 调度和分配的基本单位
  • 进程 = 独立分配资源的单位

💡 教材例子：文件服务进程里设多个服务线程，一个受阻另一个继续跑 → 显著提高文件系统服务质量与系统吞吐量。有资源的基本单位不用频繁切换，进一步提高并发程度。

⚖️线程的关键性质

轻型进程

线程具有许多传统进程的特性，故称为 Light-Weight Process

基本不拥有资源

只拥有一点运行中必不可少的资源：程序计数器、一组寄存器、栈

共享进程资源

可与同属一个进程的其他线程共享该进程拥有的全部资源

三态齐全

线程也有就绪、运行、阻塞三种基本状态；可创建另一个线程；同进程内多线程可并发

🔀两类线程

  • 用户级线程：不依赖内核，创建/撤销/切换都不利用系统调用。
  • 内核支持线程：依赖内核，无论用户进程中的还是系统中的线程，创建/撤销/切换都利用系统调用实现。

3.6.3 存储器管理 · 五种方案总览

🎯管理对象与目标

管理对象是主存存储器（内存）。它是计算机系统中的关键性资源。

主要功能：

  • 主存空间的分配和回收
  • 提高主存的利用率
  • 扩充主存
  • 对主存信息实现有效保护

主要目的：解决多个用户使用主存的问题。

🗂️五种存储管理方案

① 分区存储管理

早期方案，把主存用户区划分成若干区域，每区给一个作业，限定只能在自己区域内运行

② 分页存储管理

地址结构 = 页号 P ＋ 页内地址 W；用页表记录每页对应的物理块号

③ 分段存储管理

作业地址空间划分为若干段（主程序段/子程序段/数据段/堆栈段），各段长度不等；用段表记录基址与段长

④ 段页式存储管理

先分段，段内再分页；同时配置段表和页表

⑤ 虚拟存储管理

作业只部分装入主存即可启动运行，其余留在磁盘，需要时再调入

演进主线：分区 → 分页 → 分段 → 段页式 → 虚拟存储（从整体划分到细粒度离散分配，最后引入"部分装入"）

分区 · 分页 · 分段 存储管理

🧱分区存储管理

按划分方式分三种：

固定分区 — 静态分区方式

可变分区 — 动态分区方式

可重定位分区 — 移动已分配分区使之连续，减少内存碎片

📄分页存储管理

地址结构 = 页号 P ＋ 页内地址 W

为每个进程建一张页面映射表（页表），记录进程的每个页面对应的物理块号。

页表的作用 = 实现从页号到物理块号的地址映射

地址变换：页号与页表长度 L 比较 → 页号 ≥ L 则越界中断；否则查页表得物理块号，与页内地址拼接。

教材例：逻辑页号 4 → 查页表得物理块号 15 → 与页内地址 256 拼接 → 物理地址 15256

📚分段存储管理

作业地址空间划为若干段，每段是一组完整的逻辑信息（主程序段、子程序段、数据段、堆栈段），各段长度不等。

逻辑地址 = 段号（名） ＋ 段内地址

每段分配一个连续分区，各段可离散分配到主存不同分区；建段表记录基址和段长。

双重越界检查：① 段号 S ≥ 段表长度 L → 越界；② 段内地址 d ≥ 段长 SL → 越界。都通过则 基址 S′ ＋ d ＝ 物理地址。

⚠️ 关键辨析：分页的页是定长的（物理划分，对用户不可见）；分段的段是变长的（逻辑划分，按程序逻辑，对用户可见）——这是两者的本质区别。

段页式 与 虚拟存储管理

🧩段页式存储管理

基本原理：先将整个主存划分成大小相等的存储块（页框）；将用户程序按逻辑关系分为若干段并赋予段名；再将每个段划分为若干页，以页框为单位离散分配。

地址结构 = 段号 ＋ 段内页号 ＋ 页内地址（三部分）

同时配置段表和页表，段表中的内容是页表的起始地址和页表长度。

变换三步：① 按段号 S 查段表 → 得页表起始地址；② 按页号 P 查页表 → 得物理块号 b；③ 把 b 与页内地址 W 拼接 → 物理地址。

🪄虚拟存储管理

前面的方案都必须为作业分配足够空间装入全部信息；虚拟存储让作业只部分装入主存便可启动运行，其余部分暂留在磁盘，需要时再调入。

⭐ 虚存容量由计算机的地址结构决定（不是由主存＋外存实际大小任意决定）。

它的逻辑容量由主存和外存容量之和以及 CPU 可寻址范围共同决定；运行速度接近主存。

三种实现方式：

  • 请求分页系统 — 分页 + 请求调页 + 页面置换（最常用）
  • 请求分段系统 — 分段 + 请求调段 + 分段置换
  • 请求段页式系统 — 段页式 + 请求调页 + 页面置换

程序局限性原理（1968 年 P. Denning 提出）：

  • 时间局限性 — 某条指令/存储单元一旦被访问，不久后可能再次被访问。典型原因：程序中存在大量循环操作
  • 空间局限性 — 访问了某单元，则其附近单元也最可能被访问。典型原因：程序的顺序执行

工作集理论（1968 年 P. Denning 提出）：

把某进程在时间 t 的工作集记为 W(t, Δ)，Δ 称为工作集窗口尺寸。

工作集＝在某段时间间隔 Δ 里，进程实际要访问的页面的集合。

正确选择 Δ 的大小，对存储器有效利用和系统吞吐量有重大影响。

页面置换算法 ⭐⭐ 与 抖动

算法规则与评价
OPT 最佳置换选择永不使用或最长时间内不再被访问的页面置换出去。性能最好但实际难以实现（无法预知未来），通常用来评价其他算法
FIFO 先进先出淘汰最先进入主存、即驻留时间最久的页面。实现简单（队列＋指针）；最直观、性能最差，且有 Belady 异常
LRU 最近最少使用选择最近最少使用的页面淘汰。每页设一个访问字段记录自上次被访问以来经历的时间 T，淘汰 T 最大的页面。需要硬件支持（寄存器或栈）
NUR 最近未用LRU 的近似算法。每页设一位访问位，所有页面链成循环队列；访问时置 1，淘汰时检查访问位：为 0 则换出，为 1 则置 0 后检查下一页

口诀：OPT 最理想不可实现，FIFO 最差有 Belady，LRU 需硬件，NUR 是 LRU 的近似

📉Belady 异常（高频）

指对一个进程未分配它所要求的全部页面时，有时会出现分配的页面数增多，但缺页率反而提高的异常现象。

只有 FIFO 会出现 Belady 异常；LRU 和 OPT 不会（它们属于"栈式算法"）。

🌊抖动 / 颠簸（Thrashing）

不适当的置换算法会导致：刚被换出的页很快又被访问，需重新调入，系统频繁更换页面，以至于进程把大部分时间花在页面置换上。

解决思路：工作集理论——让进程的工作集驻留在主存中。

3.6.4 设备管理 · I/O 软件四层 与 SPOOLing

🧱I/O 设备管理软件的四个层次

① 中断处理程序（最底层）

② 设备驱动程序

③ 与设备无关的系统软件

④ 用户级软件（最上层）

目标：有利于设备独立。只要有利于这个目标，就可以为提高效率设计不同的层次结构。

读硬盘文件的完整流程：与设备无关软件检查高速缓存有无数据 → 没有则调用设备驱动程序发请求 → 用户进程阻塞等待 → 磁盘完成产生中断 → 转入中断处理程序 → 唤醒用户进程取回数据 → 用户进程继续运行。

🖨️SPOOLing 技术 ⭐

SPOOLing（Simultaneous Peripheral Operations On Line）也称外围设备联机操作。

⭐ 本质：用一类物理设备模拟另一类物理设备，使"独占使用的设备"变成多台"虚拟设备"。典型场景：打印机。

  • 组成：预输入程序 ＋ 缓输出程序 ＋ 井管理程序 ＋ 输入井和输出井（在辅助存储器上开辟的存储区域）。
  • 工作过程：初启后激活预输入程序捕获输入请求 → 把作业输入到硬盘的输入井并填作业表 → 作业需输出时先送输出井 → 输出设备空闲时由缓输出程序送到慢速输出设备。
  • 输入井中作业的四种状态：提交状态（正从输入设备预输入）→ 后备状态（预输入结束但未被选中）→ 执行状态(被选中运行，可读输入井、写输出井) → 完成状态（已撤离，结果等待缓输出）

磁盘调度算法 ⭐（要会算）

为什么需要调度：磁盘可被多个进程共享，但每一时刻只允许一个进程启动磁盘做 I/O，其余等待。访问磁盘最耗时的是寻道时间，所以磁盘调度的目标是使平均寻道时间最少。

调度分移臂调度（先）和旋转调度（后）两类。

算法规则评价
FCFS 先来先服务按进程请求访问磁盘的先后次序进行调度公平、简单，每个请求都能依次处理，不会饥饿；但未优化寻道，平均寻道时间可能较长
SSTF 最短寻道时间优先选择要求访问的磁道与当前磁头所在磁道距离最近的进程每次寻道时间最短；但不能保证平均寻道时间最短
SCAN 扫描算法既考虑距离，更优先考虑磁头当前移动方向：沿当前方向访问到再无更远磁道时才换向磁头规律颇似电梯运行，故又称电梯调度算法；避免了饥饿现象
CSCAN 单向扫描规定磁头只做单向移动（到头后快速返回起点，再单向扫描）解决 SCAN 的问题：刚扫过的磁道又来请求时，在 SCAN 下要等一整轮，被严重推迟

口诀：FCFS 公平但慢，SSTF 贪心不最优，SCAN 像电梯不饿死，CSCAN 只走单程

⚠️ 计算题套路：按算法列出访问顺序 → 累加相邻磁道距离 → 除以请求数得平均寻道长度。注意问的是"总距离"还是"平均"。

📑文件的逻辑结构（用户视角）

无结构的流式文件 — 由一串顺序字符流构成

🗄️文件的物理结构（存储视角）

即文件在物理存储设备上的存放方法，决定了逻辑块号到物理块号的转换。

① 连续结构

② 链接结构

③ 索引结构

④ 多物理块索引表

⭐ UNIX 文件系统采用三级索引结构，inode 是基本构件，表示文件系统树状结构的结点。索引表项分 4 种寻址方式：直接寻址、一级间接、二级间接、三级间接。

📁文件目录 与 路径名

为按名存取，系统为每个文件设置描述和控制文件的数据结构 —— 文件控制块（FCB），至少包括文件名和物理地址。FCB 的有序集合称为文件目录（也称目录项）。

  • 三种目录结构：一级目录 · 二级目录 · 多级目录
  • 路径名：从根目录开始到该文件的通路上所有各级目录名拼起来。目录名与文件名之间用分隔符隔开——MS-DOS 用 "\"，UNIX 用 "/"。
  • 绝对路径名：从根目录 "/" 开始的完整文件名。
  • 文件系统的六大功能：按名存取 · 统一的用户接口 · 并发访问和控制 · 安全性控制 · 性能优化 · 差错恢复

文件存储空间管理 与 共享保护

🗃️空闲空间管理四法

方法要点
① 位示图建立一张位示图（Bitmap），每一位对应一个物理块，0/1 分别表示空闲/占用。大小由磁盘物理块总数决定，描述能力强，适合各种物理结构
② 空闲区表为所有连续的空闲区建表，表项含序号、首块号、块数、状态。适用于连续文件结构
③ 空闲块链每个空闲块中存指向下一个空闲块的指针，构成链表。不需要磁盘分配表，节省空间
④ 成组链接法UNIX 系统采用。空闲块分成若干组（如每 100 块一组），每组第一个空闲块登记下一组的物理盘块号和空闲块总数。某组首块号等于 0 意味该组是最后一组

速记：位示图适合各种结构，空闲区表配连续文件，空闲块链省空间，成组链接是 UNIX

🔗文件的共享：两种链接

硬链接（基于索引结点的链接）：将两个文件目录表目指向同一个索引结点，从而达到共享。

  • 符号链接：建立新的文件或目录，与原路径名进行映射；访问时通过映射找到原文件路径再访问。
  • 优点：可跨越文件系统，甚至通过网络连到任何地方的计算机中的文件
  • 缺点：读取符号链接的共享文件比硬链接增加读盘次数

🔐文件的保护：四种存取控制

① 存取控制矩阵 — 二维矩阵，行是用户、列是文件，元素 Aij 表示权限（R/W/X 及组合）。概念清楚，但用户和文件多时占巨大存储、验证耗系统时间

② 存取控制表 — 按用户对文件访问权限的差别对用户分类，使表大大简化

③ 用户权限表 — 以用户或用户组为单位，把可存取的文件集中成表（相当于矩阵一行的简化）

④ 密码 — 创建文件时提供密码，存盘时用密码对文件内容加密

🛡️文件系统的安全与可靠性

  • 可靠性：系统抵抗和预防各种物理性破坏和人为性破坏的能力。文件系统被破坏往往后果更严重——很多情况下无法恢复。

📋作业的基本概念

  • 作业步：如源程序要经过编译、连接、装入、执行等步骤，其中每一个步骤称为一个作业步。

程序 ＋ 数据 ＋ 作业说明书

  • 联机控制：通过终端输入命令控制

作业调度算法 与 用户界面

📐响应比高优先算法

选择响应比高的作业优先启动运行。

Rp ＝ 作业响应时间 ÷ 作业执行时间

其中作业响应时间 ＝ 等待时间 ＋ 作业执行时间，所以也可写为：

Rp ＝ 1 ＋ 等待时间 ÷ 作业执行时间

每次调度前都要重算所有后备作业的响应比，选最高的执行 → 算法复杂、系统开销大。

其他常用算法：先来先服务（FCFS）· 短作业优先 · 优先级调度算法

📊调度性能的衡量指标

设作业 Ji 的提交时间 tsi、执行时间 tri、完成时间 toi：

周转时间 Ti ＝ toi − tsi

带权周转时间 Wi ＝ Ti ÷ tri

n 个作业的平均周转时间 T 和平均带权周转时间 W 分别是上述指标的算术平均。

⭐ 关键结论：作业的执行时间 tri 不能直观衡量系统性能，而带权周转时间 Wi 能直观反映系统的调度性能。

1进程三态模型中，进程从"阻塞态"转变为"就绪态"的条件是：
A等待的事件发生（如 I/O 完成）
B被处理机调度
C时间片用完
D主动放弃处理机
状态转换的判定口诀："阻塞 → 就绪"只能是外部事件驱动（等待的 I/O 完成、锁释放、信号到达）；"就绪 → 运行"是被调度；"运行 → 就绪"是时间片到 / 被抢占；"运行 → 阻塞"是主动请求等待（如请求 I/O、申请资源失败）。⚠️ 陷阱：阻塞态不能直接回到运行态——它必须先回到就绪态排队，这是本章最高频的易错点。
第3章 · 3.6 进程的三态模型与五态模型
2信号量 S 的值为 0 时，执行 P(S) 操作的结果是：
A进程被阻塞，进入阻塞态
B信号量变为 −1，进程继续执行
C信号量变为 1，进程继续执行
D进程被抢占进入就绪态
P 操作（wait / 申请）：① 若 S > 0，则 S −= 1，进程继续执行；② 若 S = 0（初值常为资源数），则进程被阻塞（挂入等待队列）。V 操作（signal / 释放）：① S += 1；② 若有进程因 P 被阻塞，则唤醒其中一个（移到就绪态）。所以 S = 0 执行 P 一定阻塞，S = 0 执行 V 一定唤醒一个。

3死锁的四个必要条件中，哪一个不是死锁的必要条件？
A资源可剥夺性
B互斥使用资源
C占有并等待资源
D循环等待资源
死锁四必要条件（必须同时满足才可能死锁）：① 互斥（资源一次只能一个进程用）；② 占有并等待（持有资源的同时又申请新资源）；③ 不可剥夺（资源不能被强行收回）；④ 循环等待（存在进程—资源的环形等待链）。破坏任一个即可预防死锁，"可剥夺性"本身不是必要条件，它恰恰是死锁的成因之一。

4关于线程与进程的关系，下列说法正确的是：
A线程是 CPU 调度的基本单位，进程是资源分配的基本单位；同一进程的线程共享该进程的地址空间
B线程与进程都是资源分配的基本单位
C同一进程内的线程不共享任何资源
D线程拥有独立的地址空间，进程不拥有
"进程 = 资源分配的基本单位，线程 = CPU 调度的基本单位"（教材经典表述）。同一进程内的多个线程共享该进程的地址空间（代码段、数据段、打开的文件、堆），但各有独立的栈与寄存器（私有部分）。这带来两大优势：① 创建/撤销开销小；② 同一进程内线程切换无需切换地址空间、通信方便（但也带来同步与数据竞争问题）。
第3章 · 3.6 线程 · 与进程的分工
5页面置换算法中，"缺页率"随进程访问的页数增加而上升，这种现象称为：
A抖动（Thrashing）
B死锁
C饥饿
D中断风暴
抖动：进程分到的物理块数不足 → 频繁缺页 → 刚调入的页又被换出 → CPU 大部分时间在页面换入换出，有效利用率骤降。解决办法：① 调整页面大小（先增后减试探）；② 增加物理块数；③ 采用局部替换策略（改 LRU 为 FIFO，或用工作集/抖动检测控制）。判定方法：统计"缺页率"曲线，如果它随分配块数增加反而上升，说明已进入抖动区。

6SPOOLing（假脱机）技术的核心作用是：
A把独占设备改造为共享设备，利用磁盘作为缓冲区实现虚拟设备
B提高磁盘的寻道速度
C压缩文件的存储空间
D加密打印数据防止泄露
SPOOLing（Simultaneous Peripheral Operations On-Line）= 假脱机 / 不联机操作：用磁盘上的"井"区作为缓冲区，把独占设备（如打印机）改造为可共享的虚拟设备。实现方式是增加两个进程：预输入进程（把作业从输入设备送到磁盘输入井）+ 缓输出进程（从磁盘输出井送到输出设备）。它与通道、DMA 一起是 I/O 控制的三大技术。

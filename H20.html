9.3 网络安全技术

9.3.1 防火墙 · 定义与功能

防火墙是一种隔离控制技术，在不同网域之间设置屏障，阻止对信息资源的非法访问，也可以阻止重要信息从内部网络中非法输出。

它位于两个或多个网络之间，执行访问控制策略的一个或一组系统；通常放置在外部网络和内部网络的中间，执行网络边界的过滤封锁机制。即使以硬件形式出现，本质上还是软件在进行控制。

🪣为什么需要防火墙 · 木桶原理

如果没有防火墙，整个内部网络的安全性就完全依赖于每台计算机——所有计算机在安全水平上必须达到一致的高度。

整个网络的安全水平是由安全水平最低的那台计算机决定的，这就是"木桶原理"。网络规模越大，统一管理水平越难。

💡 有了防火墙：内部计算机不再直接暴露给 Internet 攻击；对整个内部网络的安全管理变成防火墙的安全管理。

⚙️防火墙的功能（8 项）

访问控制功能核心

内容控制功能—

全面的日志功能审计最佳措施

集中管理功能—

自身的安全和可用性—

流量控制—

网络地址转换 NAT缓解地址短缺、隐藏内部结构

虚拟专用网 VPN—

口诀：控制 · 内容 · 日志 · 管理 · 自身 · 流量 · NAT · VPN——八字诀

9.3.1 防火墙分类与三种体系结构

🗃️两大类 + 六种细分

网络级防火墙：防止整个网络出现外来非法入侵。

例：分组过滤（检查流入信息，拒绝不符合准则的数据）、授权服务器（检查登录合法性）

应用级防火墙：由应用程序进行接入控制，通常用应用网关或代理服务器区分各种应用。

例：只允许 WWW 应用，阻止 FTP 应用

六种细分：包过滤型 · 电路级网关型 · 应用网关型 · 代理服务型 · 状态检测型 · 自适应代理型

🏰三种体系结构

① 双宿 / 多宿主机模式

一台装两块或多块网卡的堡垒主机做防火墙，分别连内网和外网；一般采用代理服务，必须禁止网络层的路由功能

② 屏蔽主机模式

由包过滤路由器 + 堡垒主机组成；堡垒主机安装在内部网，是外部网络唯一可直接到达的主机
实现了网络层和应用层安全，比单独包过滤或应用网关更安全；过滤路由器配置正确与否是安全的关键——路由表被破坏，堡垒主机就可能被绕过

③ 屏蔽子网模式（含 DMZ）

两个包过滤路由器 + 一个堡垒主机，在内外网之间建立被隔离的子网，称非军事区 DMZ（边界网络）
堡垒主机、Web、Mail 等公用服务器放 DMZ；内外网均可访问屏蔽子网，但禁止它们穿过屏蔽子网通信；即使堡垒主机被控制，内部网仍受内部包过滤路由器保护

9.3.1 防火墙的局限性 ⭐（必考）

🚧教材列举的五条局限

① 服务受限

为提高安全性限制或关闭一些有用但存在安全缺陷的网络服务，给用户带来不便

② 防外不防内

对来自网络内部的攻击还无能为力；作为被动防护手段，不能阻止不断出现的新威胁，不能有效防范数据驱动式攻击

③ 防不了绕过

不能防范不经过防火墙的攻击——例：内部用户通过 SLIP 或 PPP 直接进入 Internet

④ 不完全透明

可能带来传输延迟、瓶颈和单点失效等问题

⑤ 防不了病毒

不能完全防止受病毒感染的文件传输；若要检查所有病毒代码，效率会降到不能忍受

💡 一句话总结（教材）：防火墙只是整个网络安全防护的一个部分，需要与密码技术、访问控制、权限管理和病毒防治等其他防护措施配合使用，才能最终提供一套一体化解决方案。

口诀：防外不防内 · 不防病毒 · 不防绕过 · 有延迟瓶颈 · 限服务

⚠️ 常考判断题："部署了防火墙，内部网络就安全了" → 错。

防火墙不能防内部攻击、不能防病毒、不能防绕过它的连接。

9.3.2 虚拟专用网 VPN

VPN 是企业网在 Internet 等公共网络上的延伸，通过一个私有的通道在公共网络上创建一个安全的私有连接。

从本质上说，VPN 是一个虚信道，用来连接两个专用网，通过可靠的加密技术保证安全性，并且是作为公共网络的一部分存在的。

🧰VPN 的五项关键技术（教材列举）

① 隧道技术

VPN 的基本技术。在公用网建立一条数据通道（隧道），让数据包通过隧道传输

② 加解密技术

数据通信中较成熟的技术，VPN 可直接利用现有技术

③ 密钥管理技术

如何在公用数据网上安全地传递密钥而不被窃取

④ 身份认证技术

通常使用名称与密码或卡片式认证等方式

⑤ 访问控制技术

由 VPN 服务提供者根据预定义组中的用户身份标识限制访问

PPP 拨号会话四阶段**（隧道底层）：

创建 PPP 链路 → 用户验证 → PPP 回叫控制 → 调用网络层协议

用户验证阶段使用的两种安全认证方式：

· PAP：口令认证协议

· CHAP：挑战握手认证协议

💡 记忆要点：VPN 五技术里，隧道技术是基本技术——选择题问"VPN 的基本技术是什么"，答隧道技术。

协议对照（常考）：PPTP / L2TP 是隧道协议（数据链路层），IPSec 是网络层安全协议。

class: dense

9.3.3 安全协议层级 ⭐（必背）

层级协议要点
应用层SET（电子商务）｜ PGP（邮件）｜ HTTPS ｜ Kerberos ｜ S/MIMEHTTPS = HTTP 的安全版，使用端口 443（HTTP 是 80）；实际应用了 SSL 作为 HTTP 应用层的子层
传输层SSL / TLSSSL 由握手协议、记录协议、警报协议组成；提供三项服务：合法性认证、加密数据隐藏被传数据、保护数据完整性
网络层IPSec（AH / ESP）针对 IPv4 和 IPv6；基于端对端的安全模式；中间路由器无须支持 IPSec
数据链路层WEP / WPA / WPA2 / WPA3 ｜ PPTP / L2TP无线安全与隧道协议在这一层

SSL 的六个阶段（教材列举）：接通 → 密码交换（一般选 RSA**，也有 Diffie-Hellman、Fortezza-KEA）→ 会谈密码 → 检验 → 客户认证 → 结束。

PGP（邮件加密软件）：基于 RSA；对邮件保密以防止非授权阅读，并加数字签名**使收信人确信发送者。

原理：先用对称密钥加密信息，再将该对称密钥以接收方公钥加密组成数字信封；接收方先用自己的私钥拆封得对称密钥，再解出信息。兼顾了方便与效率。还可用于文件存储加密；承认 PGP 证书和 X.509 证书两种格式。

口诀：应用层 SET / PGP / HTTPS，传输层 SSL / TLS，网络层 IPSec，链路层 WPA

⚠️ 最常考的三个"归层"：

· SET → 应用层（电子商务安全）

· SSL/TLS → 传输层（也有说法"介于应用层与传输层之间"）

· IPSec → 网络层

· PGP → 应用层（邮件）

9.3.3 IPSec 两模式 + 9.3.4 单点登录 SSO

🛡️IPSec 的两种模式 ⭐

传输模式

只加密上层数据（IP 头明文）
主机到主机

VS

隧道模式

加密整个 IP 包（再加新 IP 头）
网关到网关（VPN 常用）

💡 IPSec 两个基本目标：保护 IP 数据包安全 + 抵御网络攻击。结合密码保护服务、安全协议组和动态密钥管理三者实现。

🚪单点登录 SSO

定义：通过用户一次性认证登录，即可获得需要访问系统和应用软件的授权；管理员不需要修改或干涉用户登录，就能方便地实现希望得到的安全控制。

采用基于数字证书的加密和数字签名技术，为合法用户签发针对各应用系统的登录票据（ticket），实现"一点登录，多点漫游"。

两种实现机制：

Kerberos 机制基于信任第三方的网络身份认证协议；验证建立在对称加密基础上；KDC 保存与所有密钥持有者通信的保密密钥；不依赖宿主机操作系统或 IP 地址

外壳脚本机制通过原始认证进入系统外壳，再激发各专用平台脚本激活目标平台账号和资源访问；简化登录，但没有提供同步的口令字

⚠️ SSO 要解决的问题（教材四条）：重复开发认证系统浪费成本 · 管理成本增加 · 用户记忆多账号口令 · 无法统一认证和授权。

9.4 访问控制

9.4 系统访问控制 · 三要素 + 五策略

访问控制是系统安全防范和保护的主要核心策略，主要任务是保证系统资源不被非法使用和访问。它规定了主体对客体访问的限制，并在身份识别的基础上，根据身份对提出资源访问的请求加以控制。

🧩访问控制三要素

主体主动实体：用户、组织、终端、应用服务程序或进程

客体被动实体：凡可被操作的信息、资源、对象（文件、记录、硬件设施等）

控制策略主体对客体的操作行为集合约束条件集（访问规则集），体现授权行为

📋访问控制五种策略

① 登录访问控制第一层访问控制；三道关卡：用户名识别验证 → 口令识别验证 → 账号默认限制检查，一关不过即不能登录

② 操作权限控制针对非法操作；用户分特殊用户、普通用户、审计用户

③ 目录安全控制控制对目录、文件和设备的操作；目录级操作对所有文件和子目录有效

④ 属性安全控制将访问属性与文件、目录、设备关联；属性安全控制级别高于用户操作权限设置级别

⑤ 服务器安全控制控制台操作：加载卸载模块、安装删除软件；提供登录限制、非法访问者检测

9.4.2 访问控制三模型 · BLP / Lattice / Biba

🔒BLP 模型 · 保密性

第一个正式的安全模型，基于强制访问控制 MAC，典型的信息保密性多级安全模型，主要应用于军事系统。

安全等级 5 级：公开、受限、秘密、机密、高密

规则：上读 + 下写

· 上读：主体不可读取安全级别高于它的数据

· 下写：主体不可写入安全级别低于它的数据

例：高密用户可读"秘密"文件但不能写入；"秘密"用户读"高密"文件会失败，但能写入

🕸️Lattice 模型 · 分域扩展

每个资源和用户都服从于一个安全类别；通过划分安全边界对 BLP 模型进行扩充，将用户和资源进行分类并允许它们之间交换信息——是多边安全体系的基础。

执行访问控制时本质上与 BLP 相同，但更注重形成"安全集束"。

前提：上读 / 下写只在相同安全集束内适用；主体与客体位于不同安全集束时不具有可比性，它们之间没有信息可以流通**。

🧬Biba 模型 · 完整性

对数据提供分级别的完整性保证，也使用 MAC。

BLP 只解决了保密问题，没有有效制约对信息的非授权修改 → Biba 弥补。

规则：下读 + 上写（与 BLP 相反）

· 下读：主体不能读取安全级别低于它的数据

· 上写：主体不能写入安全级别高于它的数据

防止非法用户创建安全级别高的客体信息，避免越权和篡改；可同时针对有层次的安全级别和无层次的安全种类

口诀：BLP 管保密（上读下写），Biba 管完整（下读上写）——两条规则正好相反

9.4.3 访问控制五分类

DAC 自主

目前计算机系统中实现最多；在确认主体身份及所属组的基础上限定访问
UNIX 类操作系统普遍采用
允许主体显式指定其他主体能否访问其资源
灵活但不安全——授权变动繁琐，易出错

MAC 强制

最早出现在 Multics 系统；TCSEC 中用作 B 级安全系统的主要评价标准

  • 每个主体、客体都有既定的安全属性，能否访问取决于两者安全属性的关系
  • 通常要求满足 BLP 两个基本特性

RBAC 角色

  • 用户 ↔ 角色 ↔ 权限
  • 特别适用于用户数量庞大、系统功能不断扩展的大型系统
  • 在大型 DBMS 的权限管理中得到普遍应用
  • 几乎可描述任何安全策略（含 DAC、MAC）

TBAC 任务

动态安全模型：权限随执行任务的上下文环境变化

  • 支持最小特权原则和最小泄露原则；权限不用即回收
  • 最显著应用：安全工作流管理系统

OBAC 对象

  • 将 ACL 与受控对象及其属性相关联
  • 允许对策略和规则进行复用、继承和派生
  • 适用于信息量巨大、内容更新变化频繁的管理信息系统

RBAC 的 4 种模型（教材）：RBAC0 基本模型（用户、角色、访问权、会话）｜RBAC1 层次模型（偏序，上层角色继承下层角色访问权）｜RBAC2 约束模型（增加约束检查）｜RBAC3** 层次约束模型（兼有 1 和 2 的特点）

口诀：DAC 看属主 · MAC 看标签 · RBAC 看角色 · TBAC 看任务 · OBAC 看对象

⚠️ 常考：企业最常用 = RBAC；军政/等保场景 = MAC；UNIX 文件权限 = DAC；工作流 = TBAC。

9.5 容灾与业务连续性

9.5.1 容灾 · RPO / RTO ⭐

灾难备份与普通数据备份的不同：它不仅备份系统中的数据，还备份系统中安装的应用程序、数据库系统、用户设置、系统参数等信息，以便在需要时迅速恢复整个系统。

💾RPO · 恢复点目标

Recovery Point Objective

灾难发生后，容灾系统能把数据恢复到灾难发生前时间点的数据。

衡量：企业会丢失多少数据

决定：备份频率

VS

⏱️RTO · 恢复时间目标

Recovery Time Objective

从系统宕机导致业务停顿时刻起，到系统恢复至可以支持业务运作之时，两点之间的时间。

衡量：企业能容忍的恢复时间

决定：恢复速度

灾难恢复 6 个等级（GB/T 20988—2007）：① 基本支持 ② 备用场地支持 ③ 电子传输和部分设备支持 ④ 电子传输及完整设备支持 ⑤ 实时数据传输及完整设备支持 ⑥ 数据零丢失和远程集群支持

口诀：RPO 丢多少数据 · RTO 停多久

理想是两者都为 0，但不现实——投入应不大于对应的业务损失

9.5.1 数据容灾 vs 应用容灾 + BCP

💾数据容灾（较基础）

关注点在数据——确保原有数据不丢失或不被破坏。

· 低级别：仅需磁带库和管理软件实现异地备份

· 高级别：靠数据复制工具（卷复制软件 / 存储系统硬件控制器）实现远程复制

数据备份属于数据容灾的范畴；是保障数据可用的最后底线**

花费较低、构建简单，但恢复时间较长——应用会被中断，业务被迫停止

VS

🚀应用容灾（高可用级别更高）

在数据容灾基础上，再将执行应用处理能力复制一份——在备份站点同样构建一套应用系统。

提供不间断的应用服务，让用户请求透明地继续运行，感受不到灾难发生。

需通过更多软件实现；可使多种应用在灾难发生时快速切换，确保业务连续性。适合 7×24 连续运行的企业

BCP 业务持续性规划：在非计划的业务中断情况下，使业务继续或恢复其关键功能的一系列预定义过程**。

实施 8 阶段：项目启动 → 风险评估与消减 → 业务影响分析 → 业务持续性策略 → 开发 BCP → 人员培训与训练 → 测试与演练 → BCP 的持续维护及变更管理

BCP 主体框架四部分**：

· DRP 灾难恢复规划

· BRP 业务恢复规划

· CMP 危机管理规划

· CA 持续可用性

口诀：数据容灾保数据，应用容灾保业务

9.7 系统可靠性

9.7 系统可靠性 · 概念与故障模型

📏可靠性的四个子特性（GB/T 25000.10—2016）

① 成熟性系统避免因错误的发生而导致失效的能力

② 容错性在发生故障或违反指定接口时，系统维持规定性能级别的能力

③ 易恢复性发生失效时重建规定性能级别并恢复受影响数据的能力

④ 依从性依附于与可靠性相关的标准、约定或规定的能力

故障的三种表现形式：永久性（连续稳定失效，反映不可恢复的物理改变）｜间歇性（不稳定软硬件状态引起的偶然故障）｜瞬时性（暂时环境条件引起；不能修复，因为硬件本身没有损坏）

🧪故障模型的四个级别

逻辑级故障元器件输入/输出固定为 0 或 1；分短路 / 开路 / 桥接故障

数据结构级故障在数据结构上的表现称差错；三种：独立差错（一个二进制位改变）、算术差错（值增减 2ⁱ）、单向差错（某些位朝一个方向变）

软件故障/差错软件故障只与设计有关（软件不会疲劳、不会衰老）；差错六种：非法转移、误转移、死循环、空间溢出、数据执行、无理数据

系统级故障表现功能错误——系统输出与设计说明不一致；无故障保护机构时会造成系统失效

💡 规律：故障模型建立的级别越低，故障处理代价越低，但覆盖的故障越少。

9.7.2 可靠性指标 · 四个公式 ⭐

⏳MTTF · 平均无故障时间

从 t=0 到故障发生时系统持续运行时间的期望值：

MTTF = ∫₀^∞ R(t) dt

若 R(t) = e^(−λt)，则 MTTF = 1/λ（λ 为失效率，假设为常数）

🔧MTTR · 平均故障修复时间

可用度为 A(t) 的系统的平均修复时间：

MTTR = ∫₀^∞ A₁(t) dt

若修复率 μ(t) = μ（常数），则 MTTR = 1/μ

🔁MTBF · 平均故障间隔时间

两次故障之间必然有修复行为，因此 MTBF 中应包含 MTTR：

MTBF = MTTR + MTTF

实际应用中 MTTR 很小，通常认为 MTBF ≈ MTTF

📊系统可用性 A

某个给定时间点上系统能够按照需求执行的概率：

A = MTTF / (MTTR + MTTF) × 100% = MTTF / MTBF × 100%

教材例题：同一型号 1000 台计算机，规定条件下工作 1000 h，其中 10 台出现故障。

· 每台千小时可靠度 R(t) = (1000−10)/1000 = 0.99

· 失效率 λ = 10/(1000×1000) = 1×10⁻⁵

· MTTF = 1/(1×10⁻⁵) = 10⁵ h

口诀：MTTF 是寿命，MTTR 是修理，MTBF = 两者之和，可用度 = MTTF ÷ MTBF

9.7.3 可靠性三模型 + 9.7.4 串联与并联 ⭐

时间模型

  • 假设：t=0 时故障数为常数，随纠正逐渐减少
  • 剩余故障数 Eᵣ(τ) = E₀ / (I − E_c(τ))
  • I=指令数；需确定调试前故障数（困难）

故障植入模型

  • 植入 m 个错误，检测 n 个，其中植入错误检出 k 个
  • 固有错误数 N̂₀ = ⌈ m(n−k) / k ⌉
  • 两步查错法（两组人）： N̂₀ = ⌈ m·n / k ⌉

数据模型

  • n 次连续运行中完成指定任务的概率
  • 一次出错概率 P₁=|Eₑ|/|E|，R(n) = (1−P₁)ⁿ

⛓️串联系统（任一失效则系统失效）

R = R₁ × R₂ × … × Rₙ

λ = λ₁ + λ₂ + … + λₙ（近似公式，各子系统失效率接近 0 时才准确）

串联越多越不可靠**

🔀并联系统（全部失效才失效）

R = 1 − (1−R₁)(1−R₂)…(1−Rₙ)

只有 1 个子系统真正需要，其余 n−1 个为冗余子系统；冗余子系统增加，MTTF 也增加

并联越多越可靠**

💡 组合模型适用四条件：① 系统只有运行 / 失效两种状态 ② 可划分为不重叠子系统 ③ 子系统失效相互独立 ④ 系统状态只依赖子系统状态。

⭐ 模冗余系统 + 混联例题

🗳️模冗余系统（表决器）

由 m（m = 2n+1，n>1）个相同子系统和一个表决器组成；表决后占多数相同结果的输出作为系统输出。

只有 n+1 个或以上子系统能正常工作时，系统才能正常工作（表决器假设完全可靠）。

公式：R = Σi=n+1→m C(m,i) × R₀ⁱ × (1−R₀)^(m−i)

三模冗余 TMR（最常用）：R = R₀³ + 3R₀²(1−R₀)

🧮混联例题（教材图 9-8 类型）

某高可靠性系统：一个部件 R 串联 [ 三个 R 并联 ] 串联 [ 两个 R 并联 ] 串联一个 R。求系统可靠度。

第 1 步 · 并联段3 个并联：1−(1−R)³；　2 个并联：1−(1−R)²

第 2 步 · 串联四段相乘：R × [1−(1−R)³] × [1−(1−R)²] × R

套路先算并联块，再算串联链——从里往外化简

速算验证

  • R=0.9 时：3 并联 = 0.999；2 并联 = 0.99
  • 系统 = 0.9 × 0.999 × 0.99 × 0.9 ≈ 0.7997

TMR 速算

  • R₀=0.9 时：R = 0.729 + 3×0.81×0.1 = 0.972
  • （比单部件 0.9 高，比两并联 0.99 低）

9.8 冗余技术

9.8 冗余技术 · 四类

容错是指系统在运行过程中发生一定的硬件故障或软件错误时，仍能保持正常工作而不影响正确结果的一种性能或措施。容错技术主要是采用冗余方法来消除故障的影响。提高可靠性的技术分两类：避错（排错）技术 与 容错技术。

① 结构冗余

最常用；分静态 / 动态 / 混合
静态（屏蔽/被动冗余）：三模、多模，通过表决和比较屏蔽错误
动态（主动冗余）：故障检测、定位及恢复，多重模块待机储备，出错用备用模块顶替
混合：取二者之长，附加硬件开销相当大、成本很高，仅可靠性要求极高场合

② 信息冗余

  • 添加额外信息保证结果正确
  • 例：检错码和纠错码

符合规则的称码字，不符合的称非码字；译码时检出非码字即检错，纠错码还能纠正
应用最广：奇偶校验码 · 海明校验码 · 循环冗余校验码

③ 时间冗余

  • 以时间（降低运行速度）为代价减少硬件与信息冗余开销
  • 基本概念：重复多次进行相同的计算，称重复执行（复执）
  • 适用于时间不重要的场合；检测瞬时性故障的有效措施

④ 冗余附加

  • 为实现上述冗余技术所需的资源和技术
  • 包括程序、指令、数据，以及存放和调用它们的空间等

冗余系统处理故障的 10 个步骤：故障检测（联机/脱机）→ 故障屏蔽（使系统不受影响）→ 故障限制（防扩散）→ 复执（检测瞬时故障）→ 故障诊断（定位）→ 系统重配置（替换/隔离，可降级使用）→ 系统恢复（前向恢复 / 后向恢复）→ 重新启动（热启动/冷启动）→ 修复（脱机/联机）→ 系统重组合**

口诀：结构 · 信息 · 时间 · 附加——四类冗余

静态屏蔽 · 动态切换 · 混合最贵

⚠️ 常考：海明码属于信息冗余；复执属于时间冗余（检测瞬时故障有效）。

9.9 软件容错

9.9 软件容错 · N 版本 vs 恢复块 ⭐

👥N 版本程序设计

静态的故障屏蔽技术，采用前向恢复策略

n 个具有相同功能的程序同时执行一项计算，结果通过多数表决选择**

n 个版本必须由不同的人（小组）独立设计，用不同的方法、设计语言、开发环境和工具——目的是减少表决点上相关错误的概率

比通常开发多三个阶段：相异成分规范评审 · 相异性确认 · 背对背测试

表决算法：全等表决（布尔量）· 非精确表决（数值量，允许偏差）· Cosmetic 表决（字符串）

VS

🔄恢复块方法

动态的故障屏蔽技术，采用后向恢复策略

主块 → 验证测试 → 不过则现场恢复 → 后备块 1 → 再验证 → 后备块 2 …**

提供相同功能的主块和几个后备块；应保证主块与后备块相互独立

验证测试（可接受测试）是裁决者：完成故障检测，本身故障是共性的，必须确保正确；必须尽可能简单

比较项目恢复块方法N 版本程序设计记忆
硬件运行环境单机多机口诀：恢复块 = 串行切换（单机/后向/慢）N 版本 = 并行表决（多机/前向/快）
错误检测方法验证测试程序表决
恢复策略后向恢复前向恢复
实时性差好

💡 第三种：防卫式程序设计——不采用任何传统容错技术就能实现软件容错；通过在程序中包含错误检查代码和错误恢复代码，一旦出错就撤销错误状态、恢复到已知正确状态。

实现策略三方面：错误检测（插入状态断言）· 破坏估计 · 错误恢复。是对恢复块和 N 版本技术的一个补充，执行效率高、占用空间小、易于实现，适用于小程序或局部程序。

1关于防火墙的局限性，下列说法错误的是：
A防火墙不能防范绕过它的连接（如内部拨号上网）
B防火墙不能防范来自内部的攻击
C防火墙能完全阻止所有已感染病毒的文件传输
D防火墙不能防范全新的、未知的威胁
防火墙的局限性（必考）：不能防范绕过它的连接、不能防内部攻击、不能防病毒感染的文件传输（病毒检测需专门防病毒系统）、不能防全新未知威胁。"能完全阻止"是绝对化表述，错误。
第9章 · 9.3.1 防火墙局限性
2下列安全协议与其所在层次对应，正确的是：
ASSL/TLS 位于传输层与应用层之间；IPSec 位于网络层；SET 位于应用层
BSSL 位于网络层；IPSec 位于传输层
CHTTPS 位于网络层；SET 位于传输层
DIPSec 位于应用层；SET 位于网络层
安全协议层级（必背）：SSL/TLS 在传输层与应用层之间；IPSec 在网络层；SET（安全电子交易）、HTTPS、PGP、S/MIME、Kerberos 在应用层。
第9章 · 9.3.3 安全协议层级
3BLP 模型与 Biba 模型的关注点分别是：
ABLP 保机密性（不上读、不下写）；Biba 保完整性（不下读、不上写）
BBLP 保完整性；Biba 保机密性
C两者都只保机密性
D两者都只保完整性
BLP（Bell-LaPadula）保机密性：不上读（低级别不能读高级别）、不下写；Biba 保完整性：不下读、不上写。两者方向相反，是高频易混点。
第9章 · 9.4.2 访问控制模型
4关于 RPO 与 RTO，正确的是：
ARPO 是能容忍丢失的数据量（时间点）；RTO 是系统恢复所需的时间
BRPO 是恢复时间；RTO 是丢失的数据量
CRPO 与 RTO 含义相同
DRPO 越大越好，RTO 越小越好
RPO（Recovery Point Objective）= 能容忍丢失的数据对应的时间点，衡量丢多少；RTO（Recovery Time Objective）= 恢复所需时间，衡量停多久。两者都是越小越好、越小成本越高。
第9章 · 9.5.1 容灾
5某系统由 3 个可靠性均为 0.9 的部件串联组成，其系统可靠性约为：
A0.729
B0.9
C0.999
D0.27
串联系统可靠性 R = R1×R2×R3 = 0.9³ = 0.729。并联系统 R = 1−(1−R1)(1−R2)(1−R3) = 1−0.1³ = 0.999。串联越串越不可靠，并联越并越可靠。
第9章 · 9.7 系统可靠性
6N 版本程序设计（NVP）与恢复块方法的主要区别是：
ANVP 是静态冗余、多版本同时运行表决；恢复块是动态冗余、出错后切换备用块
BNVP 用于硬件；恢复块用于网络
C两者工作原理完全相同
DNVP 只能用于单机；恢复块只能用于分布式
N 版本程序设计是静态冗余：多个版本同时运行、表决输出结果；恢复块是动态冗余：主块运行，接受测试失败后切换到备用块重试。

考情定位

三块必考：① 加密认证（对称/非对称对比、数字信封、数字签名、摘要算法）；② 可靠性串并联计算（必考计算题）；③ 协议层级与端口辨识。

9.1 信息系统安全体系

9.1 信息系统安全体系 · 四类安全

三大安全威胁（教材归纳）：① 对系统稳定性和可靠性的破坏（外部攻击入侵、病毒破坏）；② 大量信息设备的使用维护管理问题（软硬件滥用）；③ 知识产权和内部机密材料在存储、使用、传输中的保密性、完整性、可靠性威胁——其中以保密性受威胁可能性最大。

① 实体安全

  • 保护计算机设备、设施和媒体免遭地震、水灾、火灾等破坏
  • 分环境 / 设备 / 媒体安全三方面

② 运行安全

  • 含系统风险管理 · 审计跟踪 · 备份与恢复 · 应急四个方面
  • 实质是保证系统可靠、连续运行

③ 信息安全

确保信息的保密性、完整性、可用性、可控性
分操作系统 / 数据库 / 网络 / 病毒防护 / 访问控制 / 数据加密 / 认证 7 个方面

④ 人员安全

计算机使用人员的安全意识、法律意识和安全技能

💡 信息安全的"五性"（常考填空）：保密性 Confidentiality ｜ 完整性 Integrity ｜ 可用性 Availability ｜ 可控性 ｜ 不可否认性（另有"可审查性"的说法）。

教材原话：信息安全就是确保信息的保密性、完整性、可用性和可控性。

9.1 五层安全体系 + 四个保障体系

🏗️安全防范体系五层（由下往上）

⑤ 安全管理安全技术设备管理 · 安全管理制度 · 部门与人员组织规则。管理的制度化极大影响整体安全

④ 应用安全Web 服务、邮件系统、DNS 等应用软件与数据的安全；含病毒威胁

③ 网络安全网络层身份认证 · 访问控制 · 传输保密与完整性 · 远程接入 · DNS 安全 · 路由安全 · 入侵检测 · 网络防病毒

② 操作系统安全① OS 自身缺陷（身份认证、访问控制、漏洞）② 安全配置问题 ③ 病毒威胁

① 物理层安全通信线路 · 物理设备 · 机房安全；可靠性、备份、防灾害、防干扰、UPS 保障

🛡️系统安全保障体系四件事

①建立统一的身份认证体系（认证一切实体：人、机、设备、应用）

②建立统一的安全管理体系（集中管理所有设备与端口）

③建立规范的安全保密体系（技术方案 + 保密制度）

④建立完善的网络边界防护体系（内外网之间的屏障）

木桶原理（防火墙一节会再用）：整个网络的安全水平是由安全水平最低的那台计算机决定的。

9.1 安全保护等级 · 五级（GB 17859—1999）

级名称核心特征（教材原话）适用单位
一用户自主保护级通过隔离用户与数据实现，使用户具备自主安全保护能力；对用户实施访问控制普通内联网用户
二系统审计保护级实施粒度更细的自主访问控制；通过登录规程、审计与安全性相关事件和隔离资源，使用户对自己的行为负责需要保密的非重要单位
三安全标记保护级具第二级全部功能；另提供安全策略模型、数据标记以及主体对客体强制访问控制的非形式化描述；准确标记输出信息；消除测试发现的错误地方各级国家机关、金融机构、邮电通信、能源水源、交通运输、大型工商与 IT 企业
四结构化保护级建立在明确定义的形式化安全策略模型之上；将自主和强制访问控制扩展到所有主体与客体；考虑隐蔽通道；结构化为关键与非关键保护元素；相当的抗渗透能力中央级国家机关、广播电视、重要物资储备、社会应急服务、尖端科技企业、重点科研机构、国防建设
五访问验证保护级满足访问监控器需求——仲裁主体对客体的全部访问；监控器本身抗篡改且足够小、可分析和测试；很高的抗渗透能力；扩充审计机制，安全事件时发出信号国防关键部门、依法需特殊隔离的单位

💡 记忆锚点：一自主 · 二审计 · 三标记 · 四结构 · 五验证。等级越高，安全保护能力逐渐增强。

第三级开始出现"强制访问控制"和"数据标记"；第四级开始考虑"隐蔽通道"；第五级的核心是"访问监控器"。

⚠️ 常考判断：金融机构 / 邮电 / 能源 → 第三级；国防关键部门 → 第五级。

另一套体系别混：TCSEC（美国可信计算机系统评估标准）中的 B 级用的是强制访问控制 MAC。

9.2 加密与认证技术

9.2.1 数据加密 · 对称加密

🔐加密的基本概念

加密是对数据进行编码变换，使其看起来毫无含义，但同时仍保持可恢复形式的过程。

被变换的数据称明文，变换后的数据称密文。

加密机制是最广泛使用的安全机制，有助于保护信息的机密性和完整性，有助于识别信息来源。

传统加密算法（两类）**

· 代换加密：用密文字母表代替明文字母——字母本身变，位置不变

· 置换加密：将明文字母重新排列——字母本身不变，位置变

弱点：算法和密钥密切相关，可利用字母统计知识破译

🗝️对称加密算法（私钥加密）

定义：加密密钥和解密密钥相同，或者虽然不同，但从其中任意一个可以很容易推导出另一个。

优点：具有很高的保密强度；密钥的传输需要经过安全可靠的途径。

两种基本类型：分组密码（对明文分组和密文分组运算）、序列密码（对数据流按位或字节运算）。

DES

美国数据加密标准

3DES

DES 三重

AES

128/192/256 位

IDEA

瑞士国际数据加密

RC4

流密码

⚠️ 对称加密的命门：密钥分发困难 —— n 个人两两通信需要 n(n−1)/2 把密钥；且不能实现数字签名（无法不可否认）。

9.2.1 非对称加密 + 两者对比 ⭐

非对称加密（公钥加密）：加密密钥和解密密钥完全不同，其中一个为公钥（公开），另一个为私钥（保密），并且不可能从任何一个推导出另一个。

优点：可适应开放性使用环境，可以实现数字签名与验证。

维度对称加密（私钥）非对称加密（公钥）
密钥同一把，需保密公钥公开 + 私钥保密
速度快（适合大数据量）慢（RSA 加解密要做大指数模运算）
用途大数据量加密小数据、密钥交换、数字签名
算法DES(56) ｜ 3DES ｜ AES(128/192/256) ｜ RC4 ｜ IDEARSA（基于大数分解，密钥 512 位）｜ ECC（椭圆曲线）｜ ElGamal ｜ DSA
密钥管理分发困难：n 人需 n(n−1)/2 把易（每人一对）
签名不能提供不可否认服务可实现数字签名

💡 RSA 的细节（教材原话）：密钥长度 512 位；保密性取决于将一个数分解为两个素数的问题的难度；因加密解密要做大指数模运算，速度很慢，主要用在数字签名中。

口诀：对称快而不便分发，非对称慢而便于交换——所以实际系统都是"混合加密"。

9.2 混合加密与数字信封 ⭐

🔀混合加密（实际系统的标准做法）

✉️数字信封（教材定义）

数字信封是用加密技术来保证只有规定的特定接收人才能阅读通信的内容。

步骤：

① 发送方采用对称密钥加密信息内容

② 将此对称密钥用接收方的公钥加密（这部分称数字信封）

③ 将数字信封和加密后的信息一起发送

④ 接收方先用自己的私钥打开数字信封，得到对称密钥

⑤ 再用对称密钥解开加密信息

这种技术的安全性相当高。**

💡 谁在用：HTTPS / SSL、PGP（邮件加密）都用混合加密。

SSL 教材原话："发送时信息用对称密钥加密，对称密钥用非对称算法加密，再把两个包绑在一起传送过去。"

9.2.2 认证技术 · 数字签名 ⭐

🖋️认证 vs 加密（教材原话）

加密：确保数据的保密性，阻止非法者的被动攻击（截取、窃听）。

认证（鉴别 / 确认）：确保数据发送者和接收者的真实性和消息的完整性，阻止非法者的主动攻击（冒充、篡改、重放）。

认证往往是许多应用系统中安全保护的第一道防线。

🖋️数字签名的三个必须保证

①鉴别——接收者能够核实发送者对数据的签名

②不可否认——发送者事后不能抵赖对数据的签名

③完整性——接收者不能伪造对数据的签名

🔑签名用哪把钥匙？（必考）

⚠️ 三条高频辨析：① 数字签名用私钥签、公钥验；② 签名不能保证机密性（原文明文传），只保证完整性与不可否认；③ MD5 / SHA 是摘要算法，不可逆，不是加密算法。

9.2.2 摘要算法 · MD5 / SHA / MAC

#️⃣单向 Hash 函数（杂凑函数）

特征：输入一个长度不固定的字符串，返回一串定长字符串——称为消息摘要 MD（Hash 值 / 散列值）。

Hash 函数要解决两个问题：

① 在某一特定时间内，无法查找经 Hash 操作后生成特定 Hash 值的原消息

② 无法查找两个经 Hash 操作后生成相同 Hash 值的不同消息

MD5

输出 128 位摘要
以 512 位分组处理输入，每分组分 16 个 32 位子分组；输出由 4 个 32 位分组级联

SHA-1

对长度不超过 2⁶⁴ 位的消息产生 160 位摘要
SHA 家族 5 个：SHA-1 / 224 / 256 / 384 / 512（后四者统称 SHA-2）

MAC / HMAC

  • 消息认证码
  • 完整性 + 认证（需密钥）

🧩四个概念一张表辨清

技术作用钥匙
Hash 摘要完整性（防篡改）不需要
MAC完整性 + 认证需要（对称密钥）
数字签名完整性 + 不可否认 + 身份认证私钥签 / 公钥验
加密机密性对称或非对称

口诀：Hash 只防改，MAC 带钥匙，签名不抵赖，加密管保密

SHA-1 的应用面（教材列举）：TLS、SSL、PGP、SSH、S/MIME、IPSec。SHA-1 曾被视为 MD5 的后继者；由美国国家安全局设计。

9.2.2 数字证书 + 身份认证三方式

📇数字证书（X.509）

数字证书又称数字标识，是由认证中心 CA 签发的对用户公钥的认证。

内容：CA 信息、用户信息、用户公钥、CA 签发时间和有效期等。国际遵从 X.509 体系标准。

发行者签名= CA 用自己的私钥对证书数据做数字签名（CA 对用户证书的签名）

证书链两个用户用不同 CA 的证书无法直接通信；两个 CA 之间安全交换公钥后可用证书链完成

吊销 CRL证书过期 / 用户私钥泄露 / 用户放弃 / CA 私钥泄露 → 吊销，CA 维护证书撤销列表 CRL 供查询

💡 证书不可伪造，因此存放证书的目录无须施加特别的保护（教材原话，常考判断）。

🧍身份认证三方式

① 口令认证（用户名 / 密码）

最简单最常用；但密码是静态数据、验证时在网络上传输、每次信息相同 → 极不安全

② 动态口令认证（动态令牌）

密码按时间或使用次数不断变化，每个密码只能使用一次（一次一密）；即使截获一次也无法仿冒
缺点：需时间/次数同步；输入不便

③ 生物特征识别

身体特征：指纹、掌型、视网膜、虹膜、脸型、DNA…
行为特征：签名、语音、行走步态

口诀：静态密码最不安全 → 动态口令一次一密 → 生物特征最贴身

9.2.3 密钥管理体制 · KMI / PKI / SPK

🏛️KMI · 密钥管理基础设施

适用：封闭网，以传统的密钥管理中心（KDC 密钥分发中心）为代表。

· 静态分发：预配置技术（点对点 / 一对多发 / 网格状）。银行清算、军事指挥、数据库系统中的主流技术

· 动态分发："请求、分发"机制，用于建立实时通信中的会话密钥

· 无论静态或动态，都基于秘密信道（物理通道）进行

信任逻辑：集中式的主管方管理模式 · 单位负责制 · 主内**

🌐PKI · 公钥基础设施

适用：开放网。解决了分发密钥时依赖秘密信道的问题。

基本构成：CA、数字证书库、密钥备份及恢复系统、证书作废系统、应用接口

· 服务功能：只提供数字签名服务

· 信任逻辑：第三方管理模式 · 个人负责制 · 主外

· 基础技术：加密、数字签名、数据完整性机制、数字信封、双重数字签名

· 作用特性：良好的扩展性，适于开放业务

🌱SPK · 种子化公钥

适用：规模化专用网。两种实现：

① 多重公钥 LPK（用 RSA 实现）

缺点：将种子私钥以原码形式分发；层次越多运算时间越长

② 组合公钥 CPK（用 DLP 或 ECC 实现）

克服了 LPK 的两个缺点——私钥是组合后的变量不暴露种子，公钥运算几乎不占时间，是比较理想的密钥管理解决方案

⚠️ KMI vs PKI（教材表 9-2，必背）：作用特性——PKI 良好扩展性适于开放业务，KMI 很好封闭性适于专用业务；服务功能——PKI 只提供数字签名，KMI 提供数据加密和数字签名；应用角度——PKI 主外，KMI 主内。

口诀：KMI 主内靠秘密信道，PKI 主外靠证书，SPK 靠种子组合

对称加密（DES/3DES/AES/RC/IDEA）加解密同钥、速度快、适合大数据量，但密钥分发困难；非对称加密（RSA/ECC）公私钥成对、速度慢，适合小数据量与密钥交换。DES/AES 是对称算法。

2数字信封技术中，对明文和对称密钥分别采用的处理方式是：
A明文用对称密钥加密，对称密钥用接收方公钥加密
B明文用接收方公钥加密，对称密钥用发送方私钥加密
C明文和密钥都用对称密钥加密
D明文用发送方私钥加密，密钥用接收方私钥加密
数字信封 = 用随机生成的对称密钥加密明文（快），再用接收方公钥加密这个对称密钥（解决密钥分发），接收方用私钥解开信封取出对称密钥。

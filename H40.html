易错陷阱

边缘计算不是为了"省钱"——核心是时延与自治（工业控制不能依赖云端往返）。

论文可用句

在产线智能化改造中，我把系统设计为 CPS 闭环：在设备侧部署振动、电流、温度传感器完成感知，经工业以太网与 TSN 时间敏感网络完成通信，在产线边缘节点做工艺参数推理与优化决策（计算），再把最优参数下发至 PLC 与变频器执行控制并回读实际值形成闭环。借助数字孪生在投产前完成 12 种工况仿真，将调试周期从 3 周压缩到 4 天；关键决策下沉到边缘后控制回路时延由 200ms 降至 8ms，即使云端断连也能维持本地自治运行，产线综合能耗下降 11%。

第 21 章知识骨架

21.1 CPS 定义 · 闭环四过程 · CPS vs IoT ⭐⭐⭐

🎯定义 + 本质

CPS 信息物理系统 = 计算（Cyber）+ 通信（Communication）+ 控制（Control）+ 物理（Physical） 深度融合的多维复杂系统

  • 本质：以数据为纽带，通过计算进程与物理进程的实时交互反馈，实现物理系统的安全、高效、协同、自治
  • 五大能力：可感知 · 可计算 · 可交互 · 可延展 · 自决策
  • ⚡ CPS ≠ IoT：IoT 偏"感知与联网"（物联网是 CPS 的简约应用）；CPS 强调"控制闭环"——感知只是起点，执行/反馈控制才是核心

🔄闭环四过程 ⭐⭐（案例万能骨架）

① 感知

采集物理世界状态（传感器）

② 通信

传输数据（网络）

③ 计算/决策

分析、建模、推理（平台/边缘）

④ 控制/执行

作用于物理世界（执行器）→ 回到①闭环

💡 案例答题万能四段式："感知-通信-计算-控制"——任何 CPS 场景题都按这四段组织。

21.2 三级模型 + 五层架构 + 边缘计算 ⭐⭐⭐

🏛️CPS 三级模型（递进扩展）

① 单元级 CPS

不可分割的最小单元（部件/产品）——"感知-分析-决策-执行"数据闭环；例：智能轴承 · 智能机器人 · 智能数控机床

② 系统级 CPS

多单元级经工业网络（现场总线/工业以太网）互联 → 智能产线/车间/工厂——互联互通互操作

③ 系统之系统级 SoS

系统级经工业云/工业大数据平台构建 → 企业级数字化运营

💡 递进关系：单元级 →（CPS 总线互连）→ 系统级 →（工业云/大数据）→ SoS 级。

🥞五层架构 + 边缘计算

五层（自下而上）：① 物理层（传感器/执行器/设备）→ ② 感知/接入层 → ③ 网络/传输层 → ④ 数据处理/平台层（边缘+云） → ⑤ 应用层（智能决策/人机交互）

边缘计算 ⭐

在靠近数据源侧处理——降时延 · 省带宽，是 CPS 关键技术；与云端协同（边缘实时 + 云端全局）

⚡ 案例锚：问"为什么用边缘计算"——答实时性要求 + 带宽限制 + 数据本地化安全三理由。

21.3/21.5 工业网络演进 + 控制方式 ⭐⭐

🏭工业网络演进（必背顺序）

现场总线（Profibus / CAN / Modbus）→ 工业以太网（PROFINET / EtherCAT）→ TSN 时间敏感网络（确定性低时延）→ 5G uRLLC（1ms 级低时延高可靠）→ OPC UA（统一架构，跨平台互操作）

协议栈模型

CPS 通信 = 感知层协议（RFID/ZigBee/BLE）+ 网络层（TCP/IP/5G）+ 应用层（OPC UA/MQTT）

其他开发技术

智能感知 · 虚实融合控制 · 嵌入式软件 · MBD 基于模型的定义 · CAX/MES/ERP 软件链 · SDN

🎛️控制方式 + 数字孪生 ⭐

四种控制方式：开环（无反馈）· 闭环/反馈（输出回送比较——CPS 核心）· 前馈（按扰动预先补偿）· 预测控制（模型预测未来）

⭐ 实时性是 CPS 通信的生命线

数字孪生 Digital Twin ⭐

物理实体的实时数字映射——数据驱动实现监测 · 仿真 · 预测 · 优化
三要素 = 物理实体 + 虚拟模型 + 双向数据连接
应用 = 预测性维护 · 工艺优化 · 虚拟调试

💡 CPS 开发技术：模型驱动（MBE/MDA）· 仿真（数字孪生）· 形式化验证（实时与安全关键）· 软硬件协同 · 分布式实时调度 · 容错设计——呼应 CH17。

🛡️CPS 设计要点 + 安全双管

设计要点六条：实时性 · 可靠性/安全性 · 可扩展性 · 异构集成 · 时间同步 · 能耗

安全双管 ⭐

功能安全（IEC 61508 / ISO 26262——防失效导致危害）+ 信息安全（防攻击）——缺一不可

CPS 闭环四过程（本章第一考点，教材固定表述）：① 感知（Perception）——通过传感器采集物理实体的状态（温度、压力、位置、图像）；② 通信（Communication）——通过网络传输感知数据；③ 计算（Computation）——在边缘/云端对数据做分析与决策；④ 控制（Control）——把决策结果反馈回去执行（驱动执行器改变物理实体）。⚠️ 关键在"闭环"：感知 → 传输 → 计算 → 执行控制 → 再感知，形成闭环。记住这四段式，案例题的框架基本就出来了。

2CPS 与 IoT 的本质区别是：
ACPS 具备"感知—计算—控制"的闭环，能对物理实体施加影响；IoT 更侧重"物与物的连接与感知"
BCPS 就是 IoT 的别名
CIoT 有控制能力而 CPS 没有
D两者完全相同
CPS vs IoT 的本质区别（高频辨析）：IoT（物联网）——核心是连接（Things 联网），"物与物相连、能感知"，但不一定能控制。CPS（信息物理系统）——在 IoT 基础上增加了"计算"与"控制"能力，形成 "感知 → 计算 → 控制" 的闭环，能对物理实体施加影响、改变其状态。一句话：IoT 是"看得见"，CPS 是"管得住"。⚠️ 典型例子：智能温控器（CPS，感知温度并控制空调）vs 温度传感器+上报平台（IoT，只感知不上控）。
第21章 · 21.1 CPS vs IoT
3CPS 的五层架构（自下而上）通常是：
A物理层 → 感知层 → 网络层 → 智能层 → 应用层
B物理层 → 网络层 → 感知层 → 应用层 → 智能层
C感知层 → 物理层 → 智能层 → 网络层 → 应用层
D应用层 → 智能层 → 网络层 → 感知层 → 物理层
CPS 五层架构（自下而上）：① 物理层（Physical）——物理实体与执行器（机床、车辆、阀门、传感器本体）；② 感知层（Perception）——采集数据：传感器 + 识别（RFID、条码、视觉）；③ 网络层（Network）——传输数据：现场总线、工业以太网、5G、TSN；④ 智能层（Intelligence）——处理与决策：边缘计算、云计算、模型推理、规则引擎；⑤ 应用层（Application）——面向业务：监控大屏、预测性维护、远程控制、优化调度。记忆："物理→感知→网络→智能→应用"，与 IoT 层次结构基本一致，区别在 CPS 有更强的控制闭环。
第21章 · 21.2 三级模型 + 五层架构
4关于边缘计算在 CPS 中的作用，下列说法正确的是：
A把计算下沉到靠近设备的一侧，降低时延与带宽占用，并支持断网时的本地自治
B边缘计算就是把全部计算放到云端
C边缘计算会增加时延
D边缘计算与实时性无关
边缘计算（Edge Computing）在 CPS 中的三大价值：① 降低时延——控制回路不必绕到云端往返（毫秒级 vs 几十毫秒），满足硬实时要求；② 节省带宽——原始数据在本地预处理，只上传特征/事件而非全量原始数据；③ 断网自治（本地自治）——工业现场网络抖动或断网时，边缘节点仍能维持本地控制。典型应用：工业质检（边缘推理）、智能电网（本地实时控制）、自动驾驶（车端决策不能依赖云）。这就是为什么工业 CPS 强调"边缘侧闭环"，而不是完全上云。

案例背景
背景：徐总监抛出新需求："一期管网监测只能看实时曲线，我想更进一步——建数字孪生体，能做关阀方案推演；再把 AI 质检用上，自动识别现场照片里的隐患。" 谢工立刻补充："质检要能识别违章操作，我们的模型还得再训。" 龙工却提了个硬问题："孪生体要实时映射，管网数据来源有七八个系统，时间戳都对不齐；而且推理要 GPU，现在 GPU 白天全给线上业务了。" 郑专员最后加了一条："AI 判隐患可以，但结论要能追溯、能复核，不能让机器一句话就把工单派下去。" 甘工在白板上画了两条线：一条物理线，一条数字线——他知道，这正是 CPS 与 AI 结合的典型难题。
补充资料：门站压力 → 1 s → 网关本地时钟 → 与平台偏差 300 ms；调压站甲烷 → 30 s → 网关本地时钟 → 漂移未校准；工商表 → 5 min → 表端时钟 → 偏差最大 2 min；视频/巡检照片 → 事件触发 → 终端时间 → 时区不统一；工单系统 → 业务事件 → 服务器时间 → 与 IoT 不同源 改进：NTP/PTP 统一时钟、统一坐标系与设备编码、事件时间 + 水位线处理乱序、时钟漂移告警、对齐过程留痕。
题目
  • 1（1）说明 CPS 与数字孪生的关系，以及数字孪生的作用与建设要点；
  • 2（2）说明 AI 质检（机器视觉/多模态识别）接入 CPS 的位置与实时性要求；
  • 3（3）针对"多源数据时间戳对不齐"，给出时空一致的解决方案；
  • 4（4）说明 AI 结论可追溯、可复核的设计要求（含 2026 AI 治理要求）。
参考答案要点（三色标记）
问题 1｜参考答案要点：
- 🔴 核心：🔴 核心（1）CPS 与数字孪生）：关系——CPS 强调"计算与物理过程的闭环控制"（感知—通信—计算—控制）；数字孪生是物理实体在数字空间的实时映射与仿真体，可视为 CPS 的"高保真数字镜像与推演能力"，两者一个重"闭环控制"、一个重"映射与推演"，在工程上互补。
问题 2｜参考答案要点：
- 🔴 核心：🟡 支撑（2）AI 质检接入位置与实时性）：接入位置——①边缘侧（现场摄像头/巡检终端做初步识别：是否佩戴安全帽、是否有明显泄漏迹象），优点是无网可用、隐私可控；②云端（做精细多模态复核、趋势分析与模型训练）；③结论回流——AI 结论进入CPS 闭环（自动生成隐患工单、触发提醒）。
问题 3｜参考答案要点：
- 🔴 核心：🟡 支撑（3）时空一致）：①统一时钟基准——全线部署 NTP/PTP 时钟同步，边缘网关带时间戳；②统一空间基准——统一坐标系与设备编码（GIS 与设备台账对齐）；③时间戳与序号——每条数据带采集时间与序列号，处理乱序与迟到数据（流水线用事件时间 + 水位线）；④数据对齐与插值——多源数据按时间窗口对齐，缺失做标记而非默认填补；⑤质量校验——时钟漂移告警、序列断号检测、异常值过滤；⑥可追溯——保留原始数据与对齐过程，便于复核。
问题 4｜参考答案要点：
- 🔴 核心：🔴 核心（4）可追溯与可复核）：①模型与版本留痕——每条 AI 结论记录模型版本、推理时间、输入来源、置信度；②可干预——人工可复核、可推翻结论，且保留复核记录；③置信度分级处置——高置信度可直接生成提示，中低置信度转人工复核后再生成工单（避免误判引发误派单）；④双人复核（高风险判定如"泄漏隐患"）；⑤算法备案与生成内容标识（符合 2026 AI 治理要求）；⑥数据合规——现场照片涉及人员与场所，需脱敏/授权，并限定用途与保存期限；⑦审计与抽检——定期抽检 AI 结论与人工复核的一致率，作为模型质量指标。
解析与加分项
- 🟢 加分：解析·CPS+AI 题要"孪生作用与要点 + AI 接入位置 + 时空一致 + 可追溯可复核"。
案例 100考点 · 管网系统要不要"抗量子"⭐⭐⭐
📅 时间：2026-09-18 上午 📍 地点：集团信息安全规划会👤 人物：甘工（乙方·系统分析师）、郑专员（甲方·合规专员）、徐总监（甲方·数智化信息部总监）、卢总（乙方·技术总监）、电信技术经理（第三方·电信公司）⚡ 冲突：CPS 控制指令要长期保密，郑专员提出"抗量子密码"要求，卢总觉得成本太高难度：★★★　总分：25 分　建议用时：25 分钟
案例背景
背景：郑专员把一份材料推过来："国家在推后量子密码迁移，管网控制系统生命周期十几二十年，现在的加密算法将来可能被量子计算机破解。" 卢总皱眉："抗量子密码现在还不成熟吧？换算法要动终端、边网关、平台，成本不小。" 电信公司技术经理插了一句："而且我们线路侧也涉及加密，得两边一起改。" 甘工想起这几次安全演练暴露的问题——控制指令一旦被伪造，后果是关阀或停气。他知道，这已不是"要不要花这笔钱"，而是"什么时候开始准备、怎么分步迁移"。
补充资料：一·盘点与设计 → 0~6 个月 → 资产/算法盘点；引入密码服务抽象层 → 算法台账、可替换架构；二·混合过渡 → 6~18 个月 → 新建系统用「国密 + 候选 PQC」；存量固件支持协商 → 控制指令链路签名 + 防重放；三·全面替换 → 18 个月+ → 替换剩余链路，保留双算法与回退 → 证书与密钥体系更新 约束：PQC 密钥更大 → 报文变长，须实测对实时性（≤150 ms）与包大小的影响；终端、网关、平台与电信公司须同步改造。
题目
  • 1（1）说明 CPS 信息安全的主要威胁与防护目标；
  • 2（2）说明抗量子密码（后量子密码，PQC）的背景与迁移策略；
  • 3（3）给出本项目分阶段迁移方案（含密码敏捷性设计）；
  • 4（4）说明车路云与低空经济等新兴 CPS 场景对安全与实时的共性要求。

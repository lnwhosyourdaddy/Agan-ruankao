第 18 小时 · 项目管理（二）· 配置质量风险与文档

并附全章易错辨析 + 速记卡 + 自测清单。
风险应对策略（威胁四策略 / 机会四策略）是本章的必考辨析题，配置三库是案例常客。

考情定位

五块必拿：① 配置三库（开发库不受控 / 受控库走变更流程 / 产品库已发布）；② QA vs QC（过程 vs 产品、预防 vs 检查）；③ 风险应对八策略（威胁：规避·转移·减轻·接受；机会：开拓·分享·提高·接受）；④ RACI（A 只能有一个）；⑤ 文档三类（开发 / 产品 / 管理，用户手册属产品文档）。

记忆口诀

配置三库：开发库（正在改，不受控）→ 受控库（已基线，变更要审批）→ 产品库（已发布，变更最严）。
QA vs QC：QA 管过程防缺陷（质量审计），QC 管产品找缺陷（检查测试）。
威胁四策：规避（改计划消除）· 转移（买保险/外包，转责任不消风险）· 减轻（降概率/影响）· 接受。
机会四策：开拓 · 分享 · 提高 · 接受。
RACI：R 执行（可多个）· A 问责（只能一个） · C 咨询 · I 通知。

易错陷阱

"转移"转的是责任，风险本身并未消失 —— 说"外包后风险就没了"是错误表述。
用户手册属产品文档，不属开发文档 —— 这是文档分类最高频的错分点。
资源平衡会延长工期；资源平滑不会（只用自己的浮动时间），两者别混。

论文可用句

在配置与质量管理上，我把交付物纳入三库管理：开发中的版本置于开发库，通过评审的基线版本检入受控库（变更须提交变更申请并经 CCB 审批），发布版本归入产品库。质量保障采用 QA 与 QC 双轨：QA 侧每月做一次过程审计，重点检查变更流程与评审记录的合规性（预防缺陷）；QC 侧在提测前执行静态扫描与契约测试，用帕累托图定位 TOP3 缺陷类型并针对性治理（检查产品）。

第 8 章知识骨架

8.5 配置管理 · 过程与配置项

🗃️配置管理六活动（GB/T 8566）

①编制配置管理计划（项目开发计划的一部分）

②配置标识——确定配置项 + 命名（唯一性、可追溯性）；配置管理的基础性工作

③变更管理和配置控制——最重要的任务：防止多次变更下失控混乱

④配置状态说明（状态报告）——及时准确给出配置项当前状况

⑤配置审核——验证配置项对配置标识的一致性

⑥版本控制和发行管理——版本体现继承关系；基线版本要特殊标识

📌配置项 CI 与基线

配置项：需求/设计/代码/文档/数据/工具/接口描述；判定标准 = 是否多人使用；属性 = 名称/标识符/状态/版本/作者/日期

配置 = 配置项的集合（不同形式不同版本的程序、文档、数据的集合）

基线（里程碑）：各开发阶段末尾、通过正式技术评审的阶段产品——已"冻结"，禁止跨越里程碑修改其他阶段成果。

① 功能基线（系统分析与软件定义阶段末）· ② 指派基线（需求分析阶段末的 SRS）· ③ 产品基线（组装与系统测试阶段末）

💡 对外交付的基线 = 发行基线；内部使用 = 构造基线。

配置库三库 + 权限管理

🏦三类配置库（必考排序）

① 开发库（动态系统）

开发人员个人专用工作空间；信息频繁修改、无限制——不影响项目其他部分

② 受控库（主库/受控系统）

阶段工作结束时存入工作产品；读写和修改都受控——基线住在这里

③ 产品库（备份库/静态系统）

系统测试后的最终产品；等待交付用户或现场安装

💡 流向：开发库 → 受控库 → 产品库；动态 → 受控 → 静态——考"某阶段产品应存入哪类库"。

🔑权限分配

配置管理员权限最高，为每个成员分配配置库操作权限

一般项目成员：添加 · 检入/检出 · 下载

不能有删除权限！

💡 配置库记录与配置相关的所有信息——用库中信息评价变更后果，对变更控制意义重大。

8.6 质量管理 · 三大质量模型

💎GB/T 25000.10 双模型 + McCall

使用质量模型（5 特性）

描述产品对利益相关方造成的影响：
有效性 · 效率 · 满意度 · 抗风险 · 周境覆盖

产品质量模型（8 特性）

功能性 · 性能效率 · 兼容性 · 易用性 · 可靠性 · 信息安全性 · 维护性 · 可移植性（各分子特性）

McCall 三视角

从软件运行 · 软件修改 · 软件转移三方面考查（11 特性）

⚡ 辨析：冲刺常说的"六大特性"（功能性/可靠性/易用性/效率/维护性/可移植性）= ISO 9126 旧版；GB/T 25000.10 新版是 8 特性——两套都认识，看选项年代。

💡 质量特性有正相关（可靠性与可用性互相促进）与负相关（安全性与效率是矛盾体）——设计时折中。

质量保证 QA vs 质量控制 QC ⭐⭐

⚖️核心辨析表

QA 质量保证

管过程：定期评估项目总体绩效，建立达到质量标准的信心；对最终结果+全过程负责

QC 质量控制

查结果：监测具体结果是否符合标准，找出消除不合格的方法；贯穿项目始终

关系

QC 的结果 = QA 审计的对象；QA 成果指导下一阶段 QC 与质量改进

QC 两方面：产品/服务质量控制 + 管理过程质量控制（通过项目审计）

📜质量计划与三概念

⭐ 基本准则："质量是计划出来的，而不是检查出来的"——计划先明确质量标准与质量目标

验证 = 证实规定需求已满足；确认 = 证实针对特定预期用途的需求已满足；测量 = 确定测度的值

质量度量两类：预测型（尺度度量定量 / 二元度量定性）+ 验收型（阶段检查点确认）

💡 SQA 两种人：开发人员（技术工作：可靠技术/正式评审/测试）+ 质量保证人员（计划/监督/记录/分析/报告）。

8.7 人力资源 · RAM 责任分配矩阵

🗺️人力资源计划工具

描述角色职责三工具：层次结构图 · 矩阵图 · 文本格式（职责/权力/能力/资格）

  • 组织结构图：先想清楚什么人是项目成功的关键人物、需要什么技能
  • OBS 组织分解结构：表示组织单元负责哪些工作（类似 WBS 的组织版）

🧷RAM / RACI 矩阵

  • RAM：为工作（WBS）与人（OBS）建立映射；干系人角色 = 负责 A · 参与 P · 输入 I · 评审 R · 签字 S
  • RACI 版：R = 对任务负责任 · A = 执行任务 · C = 提供信息辅助 · I = 及时得到通知

任务分配原则 = "适合优先"

💡 考法：给矩阵表格问某角色字母含义——R 是 Responsible 负责，A 是 Accountable 执行，别背反。

团队建设 + 资源平衡

🧗团队发展时期（双口径）

  • 教材 4 时期：形成期（短暂）→ 震荡期（互不了解、甚至敌对）→ 正规期/规范期（工作方式统一）→ 表现期（最大成效直至结束）
  • PMBOK 5 阶段（冲刺口径）：Forming 形成 → Storming 震荡 → Norming 规范 → Performing 成熟 → Adjourning 解散

建设措施：培训 · 集中办公 · 团队建设活动 · 恰当的奖励与表彰

💡 口径差异：教材无"解散期"；选项出现"解散"选 PMBOK 五阶段口径。

⚖️资源负荷与资源平衡

资源负荷

特定时间内进度计划所需的各种资源数量；超出可用资源 = 资源超负荷（资源冲突）

资源平衡

延迟项目任务来解决资源冲突；一种网络分析法——充分利用时差，使资源利用达到最佳状态

💡 消除超负荷两招：修改进度表 + 利用活动时差——考"资源平衡是什么方法"答网络分析法。

沟通管理 + 8.8 风险管理概念

💬沟通管理

目标：及时适当地创建/收集/发送/储存/处理项目信息；项目经理大部分时间花在沟通上

正式沟通

组织明文规定渠道；效果好、约束力强；速度慢

非正式沟通

方便、速度快、能获得正式渠道难以获得的信息；缺点 = 容易失真

⭐ 沟通渠道数 = n(n−1) / 2 —— 10 人团队 = 45 条

⚠️风险与风险管理

风险 = 项目中的不确定因素；发生后既可能带来问题、也可能带来机会

两个基本属性：随机性（发生与后果都具偶然性）· 相对性（同一风险对不同主体影响不同）

  • 风险成本：有形成本（直接/间接损失）· 无形成本（机会减少/阻碍生产率/资源错配）· 预防与控制费用
  • 风险管理六过程：计划编制 → 风险识别 → 定性分析 → 定量分析 → 应对计划编制 → 风险监控

💡 配套概念：应急计划 = 风险事件发生时采取的预先确定的措施；应急储备 = 范围/质量变更时可减少成本或进度风险的资金。

8.8 风险识别 · 定性/定量分析

🔎风险识别（反复进行）

识别已知和可预测的风险；自始至终定期进行；团队参与以形成应对措施与责任感

三步：收集资料 → 估计项目风险形势 → 根据直接/间接症状识别潜在风险

风险识别是反复的过程——判断题

📊定性分析

对已识别风险排优先级：① 可能性与影响分析（影响含时间/成本/范围）② 确定风险优先级（综合指标）③ 确定风险类型

🧮定量分析四技术

灵敏度分析 · 期望货币值分析 · 决策树分析 · 蒙特卡罗模拟

⭐ EMV = 概率 × 影响（金额）；多方案比较用决策树（呼应 CH02 决策论）

蒙特卡罗：统计模拟——关键 = 找一组随机数（精度取决于均匀性与独立性）；不适合简单单变量模型，适合多不确定因素的复杂模型；步骤 = 选变量 → 分析概率分布 → 取样本 → 模拟结果 → 分析

风险曝光度 = 概率 × 损失（冲刺补充）

💡 考法：给场景选技术——"模拟多因素变化"选蒙特卡罗；"算损失期望"选 EMV。

风险应对策略 ⭐⭐（必考辨析）

🛡️威胁（负面风险）四策略 vs 机会（正面风险）三策略

① 规避 Avoid

改变计划以消除风险或放宽目标

② 转移 Transfer

把后果转给第三方——外包 / 保险 / 合同

③ 减轻 Mitigate

降低风险概率或影响

④ 接受 Accept

被动接受 / 主动留应急储备

开拓 Exploit

确保机会肯定出现

分享 Share

把机会分给最能把握它的第三方

提高 Enhance

提高概率或扩大正面影响（机会版"减轻"）

⚡ 辨析锚点：改计划 = 规避；找保险 = 转移；降概率 = 减轻；留钱 = 接受。机会侧"提高"是减轻的镜像。

💡 防范策略 vs 响应策略：防范 = 风险发生前采取措施，必须体现在项目计划中；响应 = 事件触发才执行（不发生就不安排）。

8.9 信息（文档）管理

📚文档标准与分类

核心标准：GB/T 8567—2006《计算机软件文档编制规范》——规定 25 种文档的编制格式（可剪裁）

文档三分类：开发文档（需求/设计/测试）/ 产品文档（用户手册）/ 管理文档（计划/报告）

面向对象软件文档：总体说明 + 用例图/类图/顺序图/协作图/状态图/活动图/构件图/部署图/包图

💡 三种常用文档的内容结构（GB/T 8567）：数据需求说明（静态数据/动态数据）· 技术报告（核心 = 技术问题与解决方法）· 项目开发总结报告（核心 = 经验与教训）

🧾技术报告与总结报告亮点

技术报告最重要部分

研发中遇到的技术问题和解决方法——每个问题单独小节：现象/影响/环境 + 分析 + 解决思路

项目开发总结报告最有价值部分

经验与教训 + 对今后项目的建议

💡 静态数据 = 运行中主要作参考、长时间不变；动态数据 = 运行中变化及输入输出的数据（呼应 CH10 数据动态特性）。

全章易错辨析 TOP 10

1SV = EV−PV（进度）；CV = EV−AC（成本）——负号都是坏消息

2SPI = EV/PV；CPI = EV/AC——<1 都不好

3EAC 两算法：BAC/CPI（按当前绩效）vs AC+(BAC−EV)（剩余按原预算）

4关键路径 = 最长路径（决定总工期）；关键活动总浮动 = 0

5赶工 = 加资源增成本 vs 快速跟进 = 并行增风险

6WBS 面向可交付成果——不是活动清单、不管"怎么做"

7配置三库流向：开发库（动态）→ 受控库（受控）→ 产品库（静态）

8QA 管过程 vs QC 查结果；QC 结果是 QA 审计对象

9风险四应对：规避（改计划）/ 转移（外包保险）/ 减轻（降概率影响）/ 接受（留储备）

10管理储备不是成本基线、不是挣值的一部分；应急储备在基线内

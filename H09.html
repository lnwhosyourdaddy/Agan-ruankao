第 9 小时 · 数据库系统（一）· 三级模式与关系基础

第 5 章真题占比 9.9%（55/557）—— 是必考计算最密集的一章，范式判断年年出现。
本学时覆盖 5.1 三级模式 + 5.2 关系数据库（术语/关系代数/函数依赖/候选键）。

考情定位

四块必拿：① 三级模式（外多/概念一/内一）+ 两种独立性（物理变概念不变、逻辑变外式不变）；② 关系代数八种运算（σ选行 π选列 ⋈连接 ÷除运算）；③ 连接三兄弟递推（θ ⊃ 等值 ⊃ 自然）；④ 候选键求解（入度为 0 的属性必在键内）。

记忆口诀

三级模式：外模式多、概念模式一、内模式一。
独立性：物理变→概念不变；逻辑变→外式不变。
关系代数：并差交×、选择 σ（行）、投影 π（列）、连接 ⋈、除 ÷（"至少/全部匹配"）。
连接递推：θ 连接 ⊃ 等值连接（θ=）⊃ 自然连接（再去重复列）。

易错陷阱

「除运算」是关系代数里最容易漏掉的一个——题干出现"至少一次 / 全部 / 都"就是它。
等值连接是 θ 连接 θ="=" 的特例，自然连接还要再去掉重复属性列，三者是递进不是并列。
候选键：入度为 0 的属性必含在键内（没有别的属性能推出它），反向边不影响入度。

第 5 章知识骨架

5.1 数据库系统与 DBMS

数据库是长期存储在计算机内的、有组织的、可共享的数据集合。

数据库系统是指在计算机信息系统中引入数据库后的系统，一般由 数据库 + 数据库管理系统（DBMS） + 应用系统 + 数据库管理员（DBA） + 用户 构成。五部分，一个都不能少。

⚙️DBMS 是什么

定位一种操纵和管理数据库的大型软件，用于建立、使用和维护数据库

职责对数据库进行统一的管理和控制，以保证数据库的安全性和完整性

访问方式用户通过 DBMS 访问数据，DBA 也通过 DBMS 做维护

多用户支持多个应用程序和用户用不同方法在同时或不同时刻建立、修改和询问数据库

💡 DBMS 具有五大功能：数据定义 · 数据操作 · 数据存储与管理 · 数据维护 · 通信，且能够允许多用户使用。

🔤DDL 与 DML

DDL · 数据定义语言

Data Definition Language

供用户定义数据库的模式结构与权限约束

典型语句：CREATE / ALTER / DROP

+

DML · 数据操作语言

Data Manipulation Language

实现对数据的追加、删除等操作

典型语句：SELECT / INSERT / UPDATE / DELETE

口诀：DDL 管"结构"（Definition），DML 管"数据"（Manipulation）——大多数 DBMS 两种都提供。

三级模式 ⭐

💡 这张图要看什么：三层的数量关系——外模式可以有多个，模式和内模式各只有一个。以及三句话的"独立链"：模式是最中心，内模式依赖模式，外模式独立于内模式，应用程序依赖外模式。

两级映像与两种独立性 ⭐

🔗三个级别靠两级映射串起来

① 外模式 / 概念模式映射 —— 保证 逻辑独立性

逻辑独立性：用户的应用程序与数据库中的逻辑结构相互独立。当数据的逻辑结构改变时，应用程序不需要改变。

② 概念模式 / 内模式映射 —— 保证 物理独立性

物理独立性：用户的应用程序与存储在磁盘上的数据相互独立。当数据的物理存储改变时，应用程序不需要改变。

教材原话：三个抽象级别之间通过两级映射（外模式/模式映射和模式/内模式映射）进行相互转换，使得数据库的三级模式形成一个统一的整体。

⚠️ 相对来说，逻辑独立性比物理独立性更难实现。

因为它要求改动概念模式时，所有外模式和应用程序都不受影响。

口诀：外—概映射管"逻辑"，概—内映射管"物理"。

记法：越靠上越抽象，抽象的那一层的改动，靠它下面那道映射兜住。

💡 常考问法：

  • "改存储结构不影响应用程序" → 物理独立性
  • "改逻辑结构不影响应用程序" → 逻辑独立性

数据模型三要素与四类模型 ⭐

🧱数据模型三要素

数据模型是现实世界数据特征的抽象。它所描述的内容包括三个部分：

① 数据结构　② 数据操作　③ 数据约束

数据结构描述数据的类型、内容、性质和数据间的联系。它是数据模型的基础，数据操作和数据约束都建立在它上面

数据操作描述在相应数据结构上的操作类型和操作方式

数据约束描述数据间的语法词义联系、制约依存关系，以及数据动态变化的规则，保证数据正确、有效、相容

口诀：结构 · 操作 · 约束——"长什么样、能怎么动、不能怎么动"

🗂️四类基本数据模型

模型结构特点与代表
层次模型树状结构：每个结点可有多个孩子，但只能有一个双亲最早出现的数据模型。典型代表 IBM 的 IMS（1968 年推出），曾作为大型商用数据库系统广泛使用
网状模型用有向图表示实体类型和实体之间的联系优点：记录间联系通过指针实现，多对多联系容易实现，查询效率高缺点：编写应用程序复杂，程序员必须熟悉数据库逻辑结构层次模型是网状模型的一个特例
关系模型用表格结构表达实体集，用外键表示实体间联系优点：建立在严格数学概念基础上，概念单一、结构简单清晰、用户易懂易用；存取路径对用户透明，数据独立性和安全性好缺点：因存取路径透明，查询效率往往不如非关系模型目前应用最广：Oracle、DB2、SQL Server、Sybase、MySQL
面向对象模型用面向对象的观点描述实体的逻辑组织、对象间的限制和联系产品有 ObjectStore、Versant Developer、Suite Poet、Objectivity 等，但具体应用并不多主流做法是在关系数据库上增加对对象模型的支持（如 Oracle）

5.2 关系数据库 · 术语八件套 ⭐

关系数据库应用数学方法处理数据。最早提出将这类方法用于数据处理的是 CODASYL 于 1962 年发表的"信息代数"；之后 David Child 于 1968 年在 7090 机上实现集合论数据结构；
但系统而严格地提出关系模型的是美国 IBM 公司的 E.F.Codd。

术语英文定义与考点
属性Attribute描述一个事物的若干特征。例：学生用学号、姓名、性别、系别、年龄、籍贯来描述
域Domain每个属性的取值范围所对应的值的集合。例：学号的域是 6 位整型数，性别的域是 {男, 女}⚠️ 关系中所有域都应是原子数据（整数、字符串是；集合、记录、数组不是）
目 / 度Degree二维表关系 R(D₁,D₂,…,Dₙ) 中的 n，即属性的个数
候选码Candidate Key若关系中的某一属性或属性组的值能唯一地标识一个元组，则称其为候选码
主码Primary Key若一个关系有多个候选码，则选定其中一个为主码
主属性Prime Attribute包含在任何候选码中的属性。不包含在任何候选码中的称为非主属性
外码Foreign KeyR 中的属性或属性组非该关系的码，但它是其他关系的码
全码All-key关系的所有属性组是这个关系模式的候选码例：R(T,C,S) 教师—课程—学生，三者组合才能区分元组

口诀：候选码可以有多个，主码只能有一个；主属性 = 出现在任一候选码里的属性

⚠️ 关系模式 ≠ 关系：关系模式是型（静态、稳定），关系是它的值（动态、随时间变化）。实际应用中常把两者统称"关系"，看上下文区分。

关系代数 · 八种基本运算 ⭐

关系代数的基本运算主要有并、差、交、笛卡儿积、投影、选择、连接和除。

运算符号含义要点 / 例子
并R ∪ SR 和 S 所有元组的集合（要求元/列数相同）可交换：R ∪ S = S ∪ R
差R − SR 中有而 S 中没有的元组不可交换：R − S ≠ S − R
交R ∩ SR 和 S 相同的元组R ∩ S = R − (R − S)（可用差表示）
笛卡儿积R × SR 为 m 元、S 为 n 元 → 结果是 m+n 元的元组集合元组数 = u × v（R 有 u 个、S 有 v 个元组时）
投影πA(R)从关系中抽取指明的属性（列）竖着切 —— 选列
选择σF(R)从关系中抽取满足给定限制条件的记录横着切 —— 选行；F 是逻辑表达式
连接⋈分三种：θ 连接 / 等值连接 / 自然连接详见下一页
除R ÷ S求"对所有"语义的商关系详见下一页（含例题）

口诀：投影竖着切（选列）· 选择横着切（选行）；并交差要求同元数，笛卡儿积元数相加、元组数相乘

⚠️ 只有"并、差、交"要求两个关系元/列数相同。笛卡儿积不要求，它是"配"而不是"比"。

连接三兄弟与除运算 ⭐

🔗连接的三种

① θ 连接（Theta Join）

从两个关系的笛卡儿积中选取属性之间满足一定条件的元组
R ⋈AθB S　（A、B 为元数相等且可比的属性组）

② 等值连接

当 θ 为"="时的 θ 连接，即 R ⋈A=B S

③ 自然连接（最常考）

一种特殊的等值连接：要求比较的分量必须是相同的属性组，并且在结果集中把重复属性列去掉
自然连接 = 等值连接 + 去掉重复列

💡 外连接的三种：左外（保留左关系全部元组）｜右外（保留右关系全部元组）｜全外（两边都保留）。不匹配的部分用空值填充。

➗除运算 R(X,Y) ÷ S(Z)

  • 条件：Y 和 Z 具有相同的属性个数，且对应属性出自相同域。
  • 结果：商关系是 R 在属性 X 上投影的一个子集，该子集和 S(Z) 的笛卡儿积必须包含在 R(X,Y) 中。
  • 公式：

R÷S = π1..r−s(R) − π1..r−s( (π1..r−s(R) × S) − R )

教材例题：R(U1,U2,U3,U4) 三行；S(U3,U4) 两行 {(c,d), (e,f)}。

① 定 X、Y、Z：Z = Y = {U3,U4}，所以 X = {U1,U2}

② 取 R 在 U1,U2 上的投影：{⟨a,b⟩, ⟨c,a⟩}，与 S 做笛卡儿积

③ 检查包含关系：⟨a,b⟩ 的两行都在 R 中 ✅；⟨c,a⟩ 有一行不在 R 中 ❌

④ 结果 = {⟨a,b⟩}

口诀：除运算考的是"对所有"——"选修了全部课程的学生"这类题，就用除。

第5章 · 5.1 三级模式
2数据库系统的数据独立性中，"物理独立性"指的是：
A当内模式（存储结构）改变时，概念模式与外模式保持不变
B当概念模式改变时，外模式保持不变
C当外模式改变时，概念模式保持不变
D概念模式与内模式同时改变
物理独立性 = 逻辑独立性由内模式 / 概念模式映像保证：改存储结构（加索引、改文件组织）时，概念模式与应用程序都不受影响。逻辑独立性由外模式 / 概念模式映像保证：概念模式改了（如增加属性），外模式与应用程序不用改。口诀："物理变→概念不变；逻辑变→外式不变"。
第5章 · 5.1 两级映像与两种独立性
3关系模型中，"关系"对应的是：
A二维表（集合），元组对应行，属性对应列
B一条记录
C一个数据库文件
D一个字段
关系模型三要素：关系（二维表 / 集合）｜元组（行，一组属性值）｜属性（列，关系的某一列）。关系的三种类型：基本表（实际存储）、查询表（由基本表导出）、虚表（视图，数据库中不实际存储，只保存定义）。⚠️ 关系必须是二维表且每个分量是不可再分原子值（这是 1NF 的基础）。

4关系代数中，能完成"找出既参加 Supplier 又参加 Project 关系的所有元件编号"这类操作的是：

关系代数八种基本运算：并 ∪ / 差 − / 交 ∩ / 笛卡尔积 × / 选择 σ（行）/ 投影 π（列）/ 连接 ⋈ / 除 ÷。除运算 ÷ 用于"至少匹配全部"这类语义：`R ÷ S` 得到"在 R 中与 S 全部属性值都匹配的元组"。典型题干关键词："至少一次 / 全部 / 都"。其他：σ 选行（WHERE）、π 选列（SELECT 字段）、× 笛卡尔积（笛卡尔表）、⋈ 连接（等值连接用 =）。

5三种连接运算中，θ 连接与等值连接的关系是：
A等值连接是 θ 连接在 θ 取"="时的特例
Bθ 连接是等值连接在 θ 取"="时的特例
C两者完全等价
D两者无任何关系
θ 连接：R ⋈_θ S —— 两个关系在指定属性上满足 θ 比较条件（>、<、≥、≤、=），θ 是任意比较运算符。等值连接就是 θ = "=" 时的特例。自然连接是等值连接 + 去掉重复属性列的特例（同名属性自动合并）。三者递推关系：θ 连接 ⊃ 等值连接 ⊃ 自然连接。

补充资料：分子 → AI 接起 + 人工接起 → 仅人工接起 → AI 接起 + 人工接起；分母 → 总呼入量 → 总呼入量 → 有效呼入量；是否排除 3 秒早释 → 未排除 → 未排除 → 排除；是否排除重复呼入 → 未排除 → 未排除 → 排除（同号 5 分钟内计 1 次）；结果 → 92% → 85% → 待重算（预计 88%~89%） 治理要求：指标在 DWD/ADS 层只计算一次，报表标注口径与数据时间。

  • 4（4）说明数据挖掘在本项目可用于哪些分析。

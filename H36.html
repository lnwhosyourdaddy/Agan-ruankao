第 36 小时 · 嵌入式系统分析与设计 · 实时调度与低功耗

第 17 章是第三篇「案例实践」的第二站。嵌入式是综合知识与案例双重考点，
其中 RMS 调度计算与优先级反转两种解法几乎每年必考，属于"不背就一定错"的那种。
覆盖 17.1 概述与安全攸关 + 17.2 嵌入式数据库 + 17.3 实时调度 + 17.4 交叉开发与低功耗 + 17.5 验证。

考情定位

四块必拿：① RMS 规则与 Liu & Layland 上界（`n(2^(1/n)−1)`，n=2→0.828）；② RMS vs EDF 对比（固定 vs 动态优先级、有上界 vs 理论 100%）；③ 优先级反转的成因与两种解法（继承=锁持有者被提升，天花板=锁申请者被封顶）；④ DVFS（动态电压频率调整，动态功耗 ∝ C·V²·f）。

记忆口诀

RMS：周期短 → 优先级高（固定优先级），上界 `n(2^(1/n)−1)`。
EDF：截止期近 → 优先级高（动态优先级），理论 100% 利用率。
一句话：RMS 稳但省，EDF 猛但险。
优先级反转：L 持锁 → H 阻塞 → M 抢占 L → H 被间接阻塞。
两解法：继承（锁持有者 L 被提升）｜天花板（锁申请者被封顶到天花板）。
低功耗三层：系统级（DVFS、休眠）· 软件级（去轮询、批处理）· 硬件级（低功耗外设）。
DVFS 原理：动态功耗 ∝ C·V²·f（电压是平方项，降压最省电）。

易错陷阱

优先级继承与天花板的方向别记反：

  • 继承：锁的持有者（L）被提升 → "持有者被继承"
  • 天花板：锁的申请者（L）申请时就被封顶 → "申请者被封顶"

RMS 是固定优先级（不是动态）；EDF 才是动态。上界低的 RMS 更易分析、调度开销小。
Liu & Layland 上界不同教材近似值略有差异（n≥3 时 0.757 / 0.78 都出现过），按教材算。

论文可用句

在任务调度上，我采用 RMS（单调速率调度） 而非 EDF：RMS 是固定优先级调度，任务优先级与执行顺序可静态分析，调度开销小、可预测性强；虽然其利用率上界 `n(2^(1/n)−1)` 低于 EDF，但本系统负载设计值仅约 0.62（N=6，理论上界 0.778），有充足余量。针对嵌入式场景下的优先级反转风险，我在锁机制中引入了优先级天花板协议：任务申请锁的瞬间即被提升至该锁的天花板优先级，从而从根本上避免了"高优先级被中优先级间接阻塞"，实测消除了原有的 17 起优先级反转告警；在应用层对关键采集线程叠加 DVFS，空闲时降频降压，实测整机功耗下降 38%，而任务截止期违约率保持为 0。

第 17 章知识骨架

17.1 嵌入式系统概述 · 定义与特点

🎯定义 · 三要素 · 七特点

定义：以应用为中心、以计算机技术为基础、软硬件可裁剪，对功能/可靠性/成本/体积/功耗有严格要求的专用计算机系统
三要素 = 嵌入性 + 专用性 + 计算机系统

七大特点：① 专用性强（软硬件紧密结合、生命周期长）② 实时性强 ③ 软硬件依赖性强（必须协同设计）④ 专用处理器（低功耗/小体积/高集成）⑤ 多种技术紧密结合 ⑥ 系统透明性（用户感觉不到其存在）⑦ 系统资源受限（存储/I/O/处理能力有限）

🧩组成五部件 + 四层架构

  • 五个核心功能部件：传感器（物理量→电信号）· 处理单元 PE · 作动器（电信号→物理动作，如继电器）· 输入接口 · 输出接口
  • 四层体系架构：硬件层（微处理器/存储器/I/O）→ 中间层 = HAL 硬件抽象层 = BSP 板级支持包（隔离上下层：硬件初始化/I/O/设备配置）→ 系统软件层（RTOS/文件系统/GUI/嵌入式数据库）→ 功能层（应用软件）

💡 BSP = HAL + 设备驱动 + 启动代码——介于硬件与 OS 之间；上层开发只看 BSP 接口

多核处理器结构 + 安全攸关系统

🔬六种处理器体系结构

  • ① 单核：一个物理处理器，不支持并行 ② 多处理器：真正并行 ③ 超线程 SMT：一个物理处理器 → 多个逻辑处理器（共享执行资源）
  • ④ 多核 CMP：单芯片多个独立"执行核" ⑤ 共享 Cache 多核：执行核共享片上 Cache ⑥ 超线程 + 多核：逻辑处理器数 = 执行核 × 2

⚡ 多核提性能、降功耗体积成本，但损害系统确定性——实时系统注意

🛡️安全攸关系统（Safety 关键）

定义：不正确功能或失效会导致人员伤亡/财产损失的计算机系统（飞行控制/汽车 ECU）；Safety = 单位时间损失期望值小于规定概率

TMR 三模块冗余模式

3 个独立并行通道 + 表决器（少数服从多数）；对随机错误容错；适用于没有 fail-safe 状态的系统

监控-启动器模式

适用于有 fail-safe 状态的系统；独立传感器监控 → 出错直接转入 fail-safe 状态（只加一个传感器+监控器，不需三份冗余）

17.2 嵌入式数据库系统

💾EDBMS 定义 + 四特点

EDBMS：嵌入式系统中存储/管理数据的 DBMS——与 OS 及应用软件集成、固化在嵌入式计算机上；多用于移动信息设备（掌上电脑/手机/车载），又称移动数据库

四特点

① 嵌入性（基本特性——嵌入软件/硬件）· ② 实时性（与嵌入性相关但有嵌入性不一定有实时性）· ③ 移动性（有嵌入性必有较好移动性，反之不一定）· ④ 伸缩性（嵌入式平台千差万别）

与通用 DB 区别：存于 Flash/内存 · 无独立服务器进程 · 事务简化 · 与应用紧耦合

🗂️三分类（按功能侧重点）

嵌入式内存数据库管理系统

处理离散、简单数据；主拷贝/工作版本常驻内存（本质特征）；例：eXtremeDB · SolidDB · FineDB

嵌入式实时数据库管理系统

处理连续实时数据流；实时存储与处理；正确性还依赖逻辑结果产生的时间；多为内外存结合两级存储

移动数据库管理系统

处理远程数据；支持移动计算（断接/同步）

💡 辨析：所有实时 DB 以内存 DB 为基础，但实时 DB 不一定是纯内存 DB；典型产品还有 SQLite、Berkeley DB。

17.3 嵌入式操作系统 EOS · 分类与结构 ⭐

⚙️硬实时 vs 软实时 + EOS 五特点

硬实时 RTOS

面向控制/通信（航空航天）；峰值负载性能可预测；安全关键；典型 = VxWorks · Nucleus · μC/OS · FreeRTOS · QNX；国产 = 天脉/瑞华

软实时

面向消费电子（手机/机顶盒）；峰值负载性能降低；典型 = Android · iOS · WinCE；国产 = 鸿蒙/麒麟/翼辉

EOS 五特点：微型化 · 代码质量高 · 专业化（移植性）· 实时性强 · 可裁减可配置

🏛️结构组成 + 宏内核 vs 微内核

EOS 层次结构：硬件抽象层（系统结构抽象层/处理器变种抽象层/平台抽象层三级）· 调试代理 · 内核（任务管理/存储管理/任务间通信/异常中断管理；三构件 = 调度器（心脏）+ 内核对象 + 内核服务）· 文件系统 · 可配置组件

宏内核

用户服务与内核服务同一空间；实时性高、结构简单；缺点 = 耦合度高、移植性差

微内核

用户与内核服务不同地址空间，靠消息传递通信；结构清晰、移植性好、易扩展；缺点 = 性能偏低

💡 混合内核 = 微内核为主 + 常用模块放回内核提性能。

实时性能指标 + 调度算法分类

⏲️实时性能时间指标

任务切换时间（上下文切换）= CPU 控制权转移给另一就绪任务所需时间（保存恢复上下文 + 调度时间）；与寄存器数目和系统结构有关

中断延迟时间 = 中断发生到系统获知——受最大关中断时间影响（内核关中断 vs 应用关中断取最大）

中断响应时间 = 中断发生到开始执行用户中断服务例程；中断恢复时间 = 例程结束回到被中断代码（抢占式还要加任务切换时间）

系统响应时间 = 发请求到应答（调度延迟）——由内核任务调度算法决定

📅调度算法六组分类维度

① 软时限 vs 硬时限（尽快执行 vs 必须准时完成）· ② 周期性 vs 非周期性 · ③ 可抢占 vs 非抢占（运行到结束/阻塞 vs 高优先级可打断）

④ 静态 vs 动态（设计时定优先级 vs 运行中动态变化——静态依据：执行时间/任务周期/紧迫性）· ⑤ 单处理器 vs 多处理器（同质/异质）· ⑥ 在线 vs 离线（运行中动态收集 vs 运行前确定——离线有确定性缺灵活性）

大多数内核支持两种普遍调度：基于优先级的抢占调度（静态/动态优先级）+ 时间轮转调度（相同优先级任务轮流执行时间片；时间片过大失去意义、过小切换开销大）

💡 实际常用 = 基于优先级的抢占式时间轮转调度（同优先级轮流、高优先级可抢占）。

RMS 单调速率调度 ⭐⭐⭐（必考计算）

📈RMS = 静态固定优先级 · 周期越短优先级越高

RMS 是静态调度算法中最有效的——若一组任务能被任何静态算法调度，则 RMS 下一定可调度

  • 六个假设：所有任务周期性 · 任务间不需要同步无共享资源 · 抢占式调度 · 时限 = 下一周期开始 · 定常执行时间 · 同等重要
  • RMS 定理：Σ Eᵢ/Tᵢ ≤ n(2^(1/n) − 1)

n→∞ 时上界 ≈ ln 2 ≈ 0.693（约 70%）；设计原则：CPU 利用率保持在 60%~70%

✏️教材例 · RMA 可调度性分析

任务 1：E=20，T=100；任务 2：E=25，T=150；任务 3：E=50，T=300

利用率 = 20/100 + 25/150 + 50/300 = 53.33%

判据上界 = 3×(2^(1/3)−1) = 77.98%

→ 53.33% ≤ 77.98%，定理满足 → 系统可调度 ✅

⚡ 计算套路：算 Σ Eᵢ/Tᵢ → 算 n(2^(1/n)−1) → 比大小给结论。数字必背：RMS ≈ 0.693（70%）。

EDF 截止时间优先 + 时间轮转 + 分区调度

⏰EDF 截止时间优先（动态优先级）

优先级随执行时限变化——截止时间越近优先级越高，系统随时调整；新就绪任务按截止时间插入队列，插到队头则抢占当前任务

EDF 定理：Σ Eᵢ/Tᵢ ≤ 1（充分必要条件）
→ 可调度性上限 = 100%（CPU 利用率最高）；EDF 调度不了就没别的算法能调度

缺点：运行中动态确定优先级，实现难度大、调度开销大

⚡ 数字对照必背：RMS ≈ 0.693（70%）｜EDF = 1.0（100%）——RMS 简单开销小，EDF 利用率高开销大。

🎠时间轮转 + 分区 APPS 调度

时间轮转：相同优先级任务轮流执行时间片，释放 CPU 排到同优先级队列尾部；时间片过大失去意义、过小切换开销大；实际 = 基于优先级的抢占式时间轮转

分区 APPS 调度（IMA 航电）

静态任务调度：处理器时间划成独立时间片资源给多个分区；调度原则 = 调度单元是分区 · 分区没有优先级 · 预先确定按固定周期重复（每周期至少一个分区窗口）；基础 = TPS 时间优先调度（周期小的分区优先）→ 闲置时间片时变为优先级调度 = APPS

💡 分区调度核心价值：分区时间隔离（严格时间确定性）——综合化模块化航空电子 IMA 的基础。

优先级反转 · 两解法 ⭐⭐⭐（必考）

🔄现象：低持锁 → 高等待 → 中抢占

场景：低优先级任务 C 占用资源 → 高优先级任务 A 等待 → 中优先级任务 B 抢占 C 运行 → A 被"反转"压制

无界优先级反转

中优先级抢占低优先级的时间不确定（B 运行多久 A 就等多久）

有界优先级反转

低优先级任务占用资源的时间已知（A 只等 C 释放资源）

💡 后果：任务错失时限、时序反常；由不同优先级任务间的资源同步引起——不可避免，只能用协议降到最低。

🛠️两种解法（必背辨析）

① 优先级继承协议（动态）

持锁的低优先级任务临时提升到被它阻塞的最高优先级任务的水平；退出临界区恢复原优先级；有传递性；缺点 = 可能阻塞链、甚至死锁

② 优先级天花板协议（静态）

信号量的天花板 = 所有使用该信号量的任务中的最高优先级；任务一拿到资源就提升到天花板（当前天花板 = 使用中资源的最高天花板）；不会传递阻塞、不会死锁；一个任务只被一个任务阻塞

⚡ 一句话辨析：继承 = 动态（高优先级来等了才升）；天花板 = 静态（一拿资源就升）——天花板还防死锁。

17.4 嵌入式开发 · 交叉开发环境 ⭐⭐

🖥️宿主机/目标机 + 交叉编译

  • 交叉开发：软件在通用平台（宿主机 Host）开发，在嵌入式目标平台（目标机 Target）运行；交叉编译 = 在宿主机上生成目标机可执行代码
  • 交叉开发环境三部分：① 运行在宿主机和目标机上的交叉开发工具与实用程序 ② 目标机上高性能可裁剪的 RTOS ③ 连接宿主机与目标机的通信方式（以太网/USB/串口/ICE 在线仿真器/ROM 仿真器）

1RMS（单调速率调度 Rate Monotonic Scheduling）的调度规则是：
A周期越短的任务优先级越高（固定优先级）
B截止时间越早的任务优先级越高（动态优先级）
C按到达时间先到先服务
D优先级由用户指定
RMS（单调速率调度）：固定优先级调度算法，任务周期越短 → 优先级越高（周期小的任务执行频率高，必须优先保证）。判据很直观：周期短的任务最"急"。⚠️ RMS 是固定优先级（任务优先级事先定好，运行期不变），调度开销小、可预测性好，但利用率上界较低。Liu & Layland 上界：`U ≤ n(2^(1/n) − 1)`，n=1→1，n=2→0.828，n=3→0.757（任务越多，上界越低）。

23 个周期任务采用 RMS 调度，其 CPU 利用率上界（Liu & Layland bound）约为：

Liu & Layland 上界：`U ≤ n(2^(1/n) − 1)`，其中 n = 任务数。计算：n=1 → 1(2−1) = 1.0；n=2 → 2(√2−1) = 2×0.414 = 0.828；n=3 → 3(2^(1/3)−1) = 3×0.2599 = 0.7797 ≈ 0.78（教材常近似为 0.757，也有教材用 0.78）；n=4 → 4(2^0.25−1) = 4×0.1892 = 0.757。⚠️ 注意不同教材对 n≥3 的近似值略有差异（0.757 / 0.78 都出现过），考试按教材写的算。结论：任务数越多，RMS 的利用率上界越低。

第17章 · 17.3 EDF 截止时间优先
4"优先级反转"（Priority Inversion）问题的经典成因是：
A低优先级任务持有高优先级任务所需的锁，中优先级任务抢占低优先级，导致高优先级被间接阻塞
B高优先级任务时间片用完
C低优先级任务计算量太大
D锁的粒度太大
优先级反转三要素：① 低优先级 L 持有锁；② 高优先级 H 申请该锁并被阻塞；③ 中优先级 M 抢占 L（M 的优先级高于 L、低于 H）→ L 拿不到锁 → H 被 M 间接阻塞，优先级被"反转"了（本该 H 最高，现在 L 最低却被卡）。⚠️ 危害：M 可以不断抢占 L，形成无限期阻塞，实时系统里这是不可接受的（可能错过截止期）。两种解法：优先级继承 与 优先级天花板（见下一题）。
第17章 · 17.3 优先级反转 · 两解法
5解决优先级反转的两种方法中，"优先级天花板（Priority Ceiling）"的做法是：
A任务申请某把锁时，直接把它的优先级提升到所有可能持有该锁的任务中的最高优先级（即该锁的天花板）
B低优先级任务持有锁时临时提升到阻塞它的最高优先级任务的优先级
C不让低优先级任务持有锁
D把所有任务设为同一优先级
两种解法对比：① 优先级继承（Priority Inheritance）——"锁持有者被继承"：L 持有 H 需要的锁时，L 的优先级临时提升到 H 的优先级（直到释放锁），让 L 尽快运行完并释放。⚠️ 缺点：只在实际发生阻塞时才继承，可能有多级链式继承。② 优先级天花板（Priority Ceiling）——"锁申请者被封顶"：L 申请某把锁的瞬间，就把 L 的优先级直接提到该锁的持有者可能具有的最高优先级（天花板），此后即使被中优先级抢占也不会阻塞 H。⚠️ 优点：预防而非补救，只需一次提升、无链式继承、阻塞时间可预测。

A根据负载动态调整处理器电压与频率——负载高时升频降压满载运行，负载低时降频省电
B固定最高频率运行以保证性能
C只在系统关机时生效
D只降低电压不调整频率
DVFS（Dynamic Voltage and Frequency Scaling）：根据实时负载动态调整 CPU 的电压与频率。原理依据：动态功耗 ∝ C·V²·f（电压是平方项，降压省电效果最显著），且频率 f 降低可同步降压 V（过高频会触发"降频"保护）。典型策略：负载高 → 升频升压（高性能）；负载低或空闲 → 降频降压（省电）。⚠️ 它属于系统级低功耗设计（与软件级"减少轮询"、硬件级"选低功耗外设"并列）。
